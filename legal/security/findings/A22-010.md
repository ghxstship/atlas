# A22-010: Authentication settings below the required strength

## Severity rationale

Medium. `supabase/config.toml` is the committed source for Supabase Auth settings (`supabase config
push`). As committed, it accepts six-character passwords, checks no breached-password list, lets a
signed-in session change the password without the current one, and turns TOTP off. Section 9
requires breached-password checks and MFA with TOTP and passkeys. Exploiting this needs credential
stuffing or a stolen session, so attack complexity is high.

## Location

`supabase/config.toml` (committed version):

- line 177: `minimum_password_length = 6` (ASVS V6.2.1 needs at least 8; 15 is recommended);
- line 180: `password_requirements = ""`;
- line 223: `secure_password_change = false` (V6.2.3: a change needs the current password);
- line 298: `[auth.mfa.totp]` with `enroll_enabled = false` and `verify_enabled = false` (V6.3.3);
- line 311: `[auth.mfa.web_authn]` is commented out, so passkeys are off;
- nowhere: breached-password checking (V6.2.4, V6.2.12) or a context-specific word list (V6.1.2,
  V6.2.11).

## Reproduction

```sh
git show main:supabase/config.toml | grep -nE '^(minimum_password_length|password_requirements|secure_password_change)|^\[auth.mfa.totp\]' -A2
git grep -nIi 'leaked_password\|hibp\|breached' -- supabase packages apps   # no setting or check
```

## Impact

Weak and breached passwords are accepted, and a hijacked session can lock the owner out by changing
the password. Orgs cannot enforce MFA per role (Section 9) while TOTP and passkeys are off.

## Suggested fix

- Set `minimum_password_length = 15` (or at least 8, with a documented reason) and keep
  `password_requirements` empty, as NIST SP 800-63B advises against composition rules.
- Set `secure_password_change = true`.
- Enable `[auth.mfa.totp]` and `[auth.mfa.web_authn]` for enrollment and verification.
- Turn on Supabase leaked password protection in the hosted project and record it in the
  deployment runbook. Add a context-specific word list check (product and org names) in the sign-up
  and password change server actions.
- Add an infra check that fails CI when these settings regress.

## Resolution

Fixed (A34, RRR-78):

- **Auth settings.** Main 560e36a (approved diff) sets, in `supabase/config.toml`:
  - `minimum_password_length = 12` and `password_requirements = "letters_digits"`;
  - `secure_password_change = true`;
  - TOTP and WebAuthn MFA enroll and verify on, and passkeys on, with a local WebAuthn relying party.
    MFA stays optional; orgs enforce it per role.
- **Sign-up and copy.** 79495df updates Atlas and Gateway sign-up to the same rules, adds a
  context-specific word check (product names, the email's local part and name parts; V6.1.2, V6.2.11)
  and updates the copy in en-US and es-US.
- **Tests.** `apps/atlas/test/password.test.ts` and `apps/gateway/test/password.test.ts` cover the
  rules. `infra/security/test/auth-config.test.ts` fails CI if the config regresses.
- **Hosted settings.** Leaked password protection (HaveIBeenPwned) and the production WebAuthn relying
  party are dashboard settings. `infra/runbooks/hosted-security-settings.md` (49d9b2f) documents them
  for the owner to apply.
