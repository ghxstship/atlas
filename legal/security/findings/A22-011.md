# A22-011: Upload scanning is not in place

## Severity rationale

Medium. Section 9 requires MIME sniffing and virus scanning on uploads. The `attachments` bucket has
a scan state machine and fails closed: only Clean versions can be read. But nothing scans and
nothing calls `app.record_attachment_scan`, so attachments never become downloadable. The other
upload buckets (`field-media`, `onboarding-uploads`, `profile-media`, `org-brand`) have no scan step,
so their files reach other people unscanned. Uploads also trust the declared content type, and
`attachments` accepts `application/zip` with no check on its unpacked size.

## Location

- `supabase/migrations/0590_attachments.sql:28`: the `app.scan_status` enum, and
  `private.attachment_object_readable`, which requires Clean.
- `app.record_attachment_scan(uuid, boolean, text)`: has no caller in `supabase/functions`,
  `packages/platform` or `packages/integrations`.
- `supabase/migrations/0590_attachments.sql:22`: `application/zip` is allowed in `attachments`.
- The `field-media`, `onboarding-uploads`, `profile-media` and `org-brand` bucket definitions carry
  no scan gate.

## Reproduction

```sh
git grep -nI "record_attachment_scan" -- supabase/functions packages/platform/src packages/integrations/src   # no caller
git grep -nIil "clamav\|antivirus" -- supabase packages apps                                              # no scanner
```

```sql
select id, public, allowed_mime_types from storage.buckets order by id;
-- field-media, onboarding-uploads, org-brand and profile-media have no scan state
```

## Impact

A malicious PDF or image uploaded through onboarding or field media is served to org staff without
scanning. Every attachment upload stays in Scanning, so the feature fails closed and cannot be used.

## Suggested fix

Add a scan worker, for example an Edge Function or job calling a scanning service, that reads each
new object, checks the magic bytes against the declared type and the file extension, scans it, and
calls `app.record_attachment_scan`. Extend the Clean gate to the `field-media` and
`onboarding-uploads` read policies. Reject archives over an unpacked size and entry count limit, or
remove `application/zip` from the allowlist.

## Resolution

Fixed in 49d9b2f (A34, RRR-78).

- **Scan worker.** The `upload-scan` Edge Function runs `runUploadScans` from `@xos/platform`. It claims
  `attachment.scan` jobs and checks each file's SHA-256 and its magic bytes against the declared type
  and extension. It scans through the `VirusScanner` port (`clamavScanner`, clamd INSTREAM over TCP)
  and calls `app.record_attachment_scan`, so attachments reach Clean. Infected and refused files are
  removed. Scanner outages retry and end in Scan Failed after five attempts.
- **Zip archives.** At most 1,000 entries, 100 MiB unpacked and a compression ratio of 100. Encrypted
  entries, path traversal, ZIP64 and nested archives are refused; Office containers may embed one
  another.
- **The other four buckets.** Migration 1041 adds `private.object_scans`, filled by a `storage.objects`
  trigger for field-media, onboarding-uploads, profile-media and org-brand. A restrictive read policy
  lets only the uploader read a file in field-media or onboarding-uploads until it is Clean.
  profile-media and org-brand are public buckets that no policy can gate on read. They are scanned,
  the worker removes what is not clean, and A22-004 keeps them to raster images.
- **Local scanner.** `infra/scanning/docker-compose.yaml` runs clamd for development. Its image tag
  waits on an ADR 0001 pin.
- **Hosted scanner.** Self-hosted clamd or a hosted service is an owner decision, recorded in
  `infra/runbooks/hosted-security-settings.md` and `legal/OWNER_INPUTS.md` Part C. No account was
  opened.
- **Tests.** `packages/platform/test/scanning.test.ts` uses a scripted clamd: the EICAR string is
  Infected and removed, a clean file is Clean, and it covers type, checksum and archive refusals plus
  retries. pgTAP `supabase/tests/1041_upload_scanning.test.sql` covers the gate, the worker API,
  replaced content, retries and the public buckets.
