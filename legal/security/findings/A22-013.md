# A22-013: Internal error detail in Edge Function responses

## Severity rationale

Low. Every Edge Function wraps its handler in `serve` from `_shared/runtime.ts`. An unexpected error
becomes a 500 response whose `detail` is the raw error message. Several of these functions take
unauthenticated requests (`verify_jwt = false`). The messages can name environment variables (from
`env()`: "STRIPE_WEBHOOK_SECRET is not set"), database errors and SQL fragments returned through
supabase-js, which helps an attacker map the back end.

## Location

`supabase/functions/_shared/runtime.ts:42` (`serve`) and `:53` (`detail: message`).

## Reproduction

Read the wrapper:

```sh
sed -n 42,57p supabase/functions/_shared/runtime.ts
```

Against a deployment with a database error or a missing secret, any unauthenticated POST to
`/functions/v1/inbound-email` with the right shape, or to `/functions/v1/kiosk-punch`, answers
`500 {"type":"/problems/internal","detail":"<raw message>"}`.

## Impact

Information disclosure that helps an attacker plan further attacks. No data is exposed directly.

## Suggested fix

Return a generic `detail` with a request id, and log the message with that id (it is already logged
as JSON). Keep specific problem types for known refusals.
