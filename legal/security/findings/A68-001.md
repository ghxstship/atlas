# A68-001: iOS offline database not encrypted

## Severity rationale

Medium. Section 13 and the encryption policy (`legal/policies/encryption.md`) promise that Compass
keeps its offline database encrypted with SQLCipher, with the key in the Keychain. On iOS the database
was plain SQLite. iOS file protection still encrypts the file while the device is locked before its
first unlock, so the exposure needs an unlocked device, a jailbreak or an unencrypted Finder backup;
but schedules, punches with locations, incident reports and chat history were readable there, and
the store privacy answers and the ISO 27001 statement of applicability rely on the control.

## Location

- `apps/compass/package.json` sets `"op-sqlite": { "sqlcipher": true }`.
- `@op-engineering/op-sqlite/op-sqlite.podspec` reads its options from the first `package.json` it
  finds above its own folder. In this pnpm workspace the package lives in
  `node_modules/.pnpm/@op-engineering+op-sqlite@18.2.5.../node_modules/@op-engineering/op-sqlite`, so the
  first `package.json` above it is the repository root's, which had no `op-sqlite` key.
- `pod install` printed `[OP-SQLITE] Configuration found at <repo>/package.json` and
  `[OP-SQLITE] using pure SQLite`, and no `OpenSSL-Universal` pod was installed.
- Android was not affected: op-sqlite's Gradle script reads `apps/compass/package.json` (the Gradle
  root's parent), so Android builds used SQLCipher.
- `src/runtime/platform.ts` passes `encryptionKey` to `open()`, which plain SQLite ignores.

## Reproduction

```sh
cd apps/compass && CI=1 pnpm exec expo prebuild -p ios --no-install && cd ios && pod install | grep OP-SQLITE
```

## Fix

The root `package.json` carries the same `"op-sqlite": { "sqlcipher": true }`. `pod install` now prints
`using SQLCipher` and installs `OpenSSL-Universal`, the Release simulator build links
`OpenSSL.framework`, and Compass ran its store screenshot flow on it.
`apps/compass/test/store-release.test.ts` ("encrypts the offline database with SQLCipher on iOS too")
fails if the two settings ever differ.

No existing iOS install needs migrating: Compass has not shipped to TestFlight or the App Store.

## Consequences

- iOS now bundles OpenSSL (a standard algorithm, AES-256). App Store Connect's export compliance
  answers change accordingly (`apps/compass/store/ios/privacy-manifest.md`, Encryption and export
  compliance); the owner and counsel confirm them before the first TestFlight build.
