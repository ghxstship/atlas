# A22-014: Session cookie name prefix

## Severity rationale

Low. The auth cookie is httpOnly, SameSite=Lax and Secure on https, which covers the main risks.
ASVS V3.3.1 (Level 1) also requires the `__Secure-` prefix when `__Host-` is not used, and V3.3.3
(Level 2) requires `__Host-` unless the cookie must be shared across hosts. Without a prefix, a
sibling subdomain or a network attacker on plain http can plant a cookie with the same name that
the browser sends to Atlas (cookie tossing).

## Location

- `apps/atlas/lib/supabase/cookies.ts:11`: `name: "xos-auth"`.
- `apps/gateway/lib/supabase/cookies.ts:11`: `name: "xos-auth"`.
- `packages/api/src/runtime/auth.ts`: `SESSION_COOKIE = "xos-auth"`.

## Reproduction

```sh
grep -n 'name: "xos-auth"' apps/atlas/lib/supabase/cookies.ts apps/gateway/lib/supabase/cookies.ts
```

## Impact

Session fixation or confusion through a planted cookie from another host under the same site.

## Suggested fix

Rename the cookie to `__Host-xos-auth` with `path=/`, Secure and no Domain attribute in both apps
and in the API runtime. Keep a fallback name only for local http development.
