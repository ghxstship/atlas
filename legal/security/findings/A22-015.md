# A22-015: OAuth authorization server missing

## Severity rationale

Low. There is no vulnerability today, because no endpoint exists. But ADR 0003 and Section 8.5 make
OAuth 2.1 with PKCE the path for user-delegated apps, and the public docs and the OpenAPI security
scheme already point integrators at endpoints that do not exist. Fourteen Level 1 and 2 ASVS
requirements cannot be verified until the server exists.

## Location

- `packages/api/src/conventions/components.ts:350`: `authorizationUrl: "/oauth/authorize"`.
- `apps/docs/content/guides/en-US/authentication.md:25` and the es-US twin describe `/oauth/authorize`
  and `/oauth/token`.
- No route under `apps/atlas`, `apps/gateway` or `packages/api` serves either path. ADR 0024 lists
  the endpoints as open.

## Reproduction

```sh
git grep -nI '/oauth/authorize\|/oauth/token' -- apps packages/api/src
find apps -path '*node_modules*' -prune -o -path '*oauth*' -print      # nothing
```

## Impact

Integrators who follow the docs get 404s. Teams are likely to work around the gap with long-lived
API keys, which carry broader risk than delegated, revocable grants.

## Suggested fix

Build the authorization and token endpoints to ASVS V10.4: exact redirect URI allowlists, PKCE with
S256 only, codes valid at most 10 minutes and used once, refresh token rotation with absolute expiry,
revocation, and consent per request (V10.7). Until then, mark the OAuth sections of the docs and the
OpenAPI security scheme as not yet available.
