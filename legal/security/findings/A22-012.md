# A22-012: Rate limits are per process

## Severity rationale

Low. Section 9 requires rate limits per IP, per user, per API key and per token RPC. The default API
limiter keeps its windows in a `Map` inside each server instance. On Vercel, each function instance
counts on its own and starts empty on a cold start, so the effective limit is the configured limit
times the number of warm instances. Brute force of the database token RPCs is still bounded by their
own lockouts.

## Location

- `packages/api/src/runtime/rate-limit.ts:4`: "a fixed window per caller held in this process, so
  each server instance counts on its own".
- `packages/api/src/runtime/rate-limit.ts:33`: `const windows = new Map<...>()`.

## Reproduction

Two limiters stand in for two server instances. Each allows the full limit for the same caller:

```ts
const a = createWindowRateLimiter({ limit: 3 });
const b = createWindowRateLimiter({ limit: 3 });
for (let i = 0; i < 3; i += 1) {
  await a.take("key");
  await b.take("key");
}
// both report allowed: true; the caller made 6 calls against a limit of 3
```

## Impact

Credential stuffing against sign-in, and scraping through API keys, can run several times faster
than the documented limit.

## Suggested fix

Back the `RateLimiter` interface with a shared store: a Postgres function with an advisory lock (as
`private.rate_limit_exceeded` already does for token RPCs), Upstash Redis, or the Vercel firewall
rate limits. Keep the in-process limiter as a local first line.

## Resolution

Fixed in 1bd1641 (A34, RRR-78). Migration 1040 adds `private.api_rate_windows` and
`app.take_api_rate_limit`, a fixed window per `auth.uid()` counted with an atomic upsert and pruned by
cron. The API runtime's default limiter (`createSharedRateLimiter`) calls it as the caller, so every
instance shares one window. It falls back to the in-process limiter, and reports the failure, when the
database cannot answer. Tests: pgTAP `supabase/tests/1040_shared_api_rate_limits.test.sql` and
`packages/api/test/security/shared-rate-limit.test.ts` (two limiters, one shared count).
