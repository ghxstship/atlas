# A22-002: Offline replay bypassed RLS for four logistics RPCs

## Finding

`app.apply_sync_mutation` replays a device mutation through `private.sync_call`. Both functions are
SECURITY DEFINER, so the replayed RPC runs as the function owner. Four allowlisted RPCs from 0442
were SECURITY INVOKER and relied on RLS alone:

- `app.add_marshalling_entry`
- `app.record_gate_arrival`
- `app.check_in_dock_slot`
- `app.release_vehicle`

Through the sync path, RLS never applied to them. An Owner of one org passed their own org to
`apply_sync_mutation` and named another tenant's project. The rows then landed in that tenant's
marshalling log and gate queue.

## Fix

- The four RPCs are SECURITY DEFINER. Each checks the capability its table's write policy checks:
  `logistics.yard.write` or `logistics.dock_slot.write`, scoped through `private.project_ids_with`.
- `private.sync_call` refuses any RPC that is not SECURITY DEFINER.
- pgTAP 0935 asserts three things:
  - every `private.sync_rpcs` entry is SECURITY DEFINER;
  - another tenant is refused on every path;
  - a coordinator still succeeds through the sync path.
