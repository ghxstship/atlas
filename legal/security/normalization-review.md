# Gate 29 Normalization Review

Section 18 gate 29 asks an independent agent to review every migration for Third Normal Form and to
file a finding for any violation not listed in the denormalization register. A22 reviewed main
d36918a (170 migrations). A108 reviewed the 196 migrations added after it on batch-c 288be004 and
turned the method into catalog lints, so a migration added after the review fails `supabase test
db` until its exceptions are registered (ADR 0068).

## Review of batch-c 288be004 (A108)

### Scope

- Every migration added after d36918a, 196 files from `0808_workforce_form_media` to
  `1671_person_push_delivery`:
  `git diff --name-only --diff-filter=A d36918a..batch-c -- supabase/migrations`. Two earlier
  migrations were edited in that range, `0101_xpms_tables` and `0150_xpms_canon_seed` (owner
  decision 25 and A47-001); the catalog checks cover their result because they read the whole
  schema.
- The schema after `supabase db reset` of batch-c 288be004: 587 `app`, 93 `private` and 96 `xpms`
  tables, no materialized views.
- The register is `docs/adr/denormalization-register.yaml`, with its generated view
  `docs/adr/denormalization-register.md`. Each column the method finds is listed there with a kind
  and a note, and each violation names its finding.

### Method

The A22 method below, run as catalog queries over the migrated schema and kept as the pgTAP suite
`supabase/tests/1282_normalization_lints.test.sql`, then judged column by column:

1. **Arrays.** Every array-typed column in `app`, `private` and `xpms`. Arrays of uuids are refused
   outright (pgTAP 1280); the others must hold a short closed set or a payload read whole.
2. **JSON.** Every `json` and `jsonb` column, domains resolved, judged against the ADR 0002
   exceptions: rich text documents, audit diffs and provider payloads.
3. **Stored derived values.** Every non-generated column whose name has a word `total`, `count`,
   `sum`, `balance`, `score`, `percent` or `readiness`, checked for rows it could be computed from.
   A count is a `fact` only when nothing else records what it counts.
4. **Restated columns.** Every foreign key, compared column by column with the table it references:
   a column outside the key with the same name and type as a column of the parent, outside the
   parent's primary key, restates it. Names that describe the row itself (`org_id`, the row stamps,
   `name`, `description` and the like) are left out, and so are keys made only of them. Each of the
   269 pairs was read against the column comments and the guards on the table: a copy through a
   required (`not null`) key that is not registered is a finding; a value the row needs without an
   optional link, or one that can differ from the parent's, is the row's own.
5. **Closed lists.** Check constraints that hold a list of values over a text column, against
   Section 3.15 rule 3 (enums or reference tables). A check that limits an enum column to some of
   its values is not a finding.
6. **Tenant columns.** Every `app` table without `org_id` or an audit column, against ADR 0019
   item 10 and ADR 0033 decision 69. pgTAP 0202 now reads this list from the register.

### Observations below the finding threshold

- `app.form_submissions.passed` and `app.training_completions.passed` are booleans computed at
  submission from the score and the pass mark. They are fixed with the score and not matched by the
  stored-total lint's names; fix them with the score if A22-008's rows ever make it derivable.
- `xpms.playbook_sourced_value` (owner decision 25, edited into 0101) keys provenance marks by target
  table, key and column, and `value_text` keeps the Playbook value as imported. It is evidence of the
  import, not a second home for the canon value, so it is not a restatement.
- A restatement under an own name (a child `name` copied from its parent) is not caught by the lint,
  so the 12 own-name pairs in the 196 migrations were read by hand. Each is the row's own value,
  except `app.automation_run_steps.position`, which keeps the action's position as the run found it:
  a fact of the run, not a violation.

## Review of main d36918a (A22)

### Method

1. **Arrays.** The catalog was queried for every array-typed column in `app` and `private`.
2. **JSON.** Every `json` and `jsonb` column was listed with its comment and judged against the ADR
   0002 exceptions: rich text documents, audit diffs and provider payloads.
3. **Stored derived values.** Columns named like totals, counts, balances, sums, scores or
   percentages were listed and checked for a ledger or source they restate, and for
   `attgenerated`.
4. **Restated columns.** Child tables that copy a parent column (`project_id` stamped from a parent)
   were checked against the register. `org_id` on every tenant table is the ADR 0002 convention,
   derived by trigger and never accepted from the caller, so it is not a violation.
5. **Closed lists.** Lifecycle and kind columns were checked to be enums or reference tables.

### Results

| Area                                    | Result                                                                                                            |
| --------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Register entries (9)                    | Each stamped `project_id` and `private.sync_scope_grants` is registered with a refresh rule and a measured reason |
| `app.usage_rollups`                     | Registered; written once per closed month                                                                         |
| Audit, event, payload and result JSON   | Within the ADR 0002 exceptions (audit diffs, webhook payloads, Stripe events, idempotency and sync results)       |
| `report_runs`, `export_jobs` row counts | Facts about a run at the time it ran, not derivable later; not violations                                         |
| Delivery `attempt_count`                | No attempts table exists, so the count is the only record of attempts; not a violation                            |
| `invite_links.use_count`                | Memberships do not record the link they came from, so the count is not derivable; not a violation                 |
| Occupancy running totals                | Registered with a refresh rule: [A22-007](findings/A22-007.md)                                                    |
| Forms, surveys and quizzes              | Quiz keys fixed in 1042; the rest registered: [A22-008](findings/A22-008.md)                                      |
| Scope and group arrays                  | Registered with a refresh rule: [A22-009](findings/A22-009.md)                                                    |
