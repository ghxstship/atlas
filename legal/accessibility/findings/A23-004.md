# A23-004: Compass status messages are not announced on iOS

## Severity rationale

Serious. Continuous scanning, clock in and out, and offline work are the core field journeys
(Section 11.13). A VoiceOver user scanning credentials hears nothing after each scan: the result,
accepted or refused, is only drawn and buzzed. The same holds for a punch landing, a punch queued
offline, and every toast and banner. Compass calls `AccessibilityInfo.announceForAccessibility`
nowhere, and `accessibilityLiveRegion` (used twice) works only on Android.

## Location

- `apps/compass/src/ui/compass.tsx:194` (`ScanSheet` last result) and `:406` (`RunOfShowLive`
  next cue): `accessibilityLiveRegion="polite"`, Android only.
- `apps/compass/src/ui/layout.tsx:336` (`Banner`, used by `Toast` and `OfflineBanner`):
  `accessibilityRole="alert"` on a View does not announce on iOS when it mounts or changes.
- `apps/compass/app/(tabs)/today.tsx:77` to `:86`: after `clock.punch`, the new state and the
  "queued" notice render with no announcement.
- `apps/compass/app/(tabs)/scan.tsx:384`: the scan count changes silently.

## Reproduction

Source audit (no device run here; confirm on device):

1. `grep -rn announceForAccessibility apps/compass` returns nothing.
2. On an iPhone with VoiceOver, open Scan in credential mode and scan a valid then an invalid badge.
   Expected: "Accepted, Jordan Lee" and "Refused, expired". Actual: silence, haptics only.
3. Clock in while offline. Expected: "On shift, punch queued". Actual: no speech.

## Suggested fix

Add an `announce(message)` helper in the ui-native seam that calls
`AccessibilityInfo.announceForAccessibility` on iOS and keeps the live region on Android. Call it
for each scan result (with the reason on refusal), each clock state change and queued punch, each
offline queue count change (debounced), and when a Toast or Banner mounts.
