# A23-006: Compass radio controls report the wrong state

## Severity rationale

Moderate. Segmented controls (scan mode, settings choices) and the incident type grid use
`accessibilityRole="radio"` with `accessibilityState={{ selected }}`. For a radio, assistive
technology expects `checked`; TalkBack reads these as "not checked" whichever option is chosen, and
VoiceOver's announcement does not match the radio's state. The person can still find the visual
choice, but cannot hear it.

## Location

- `apps/compass/src/ui/primitives.tsx:392` (`SegmentedControl` option).
- `apps/compass/src/ui/compass.tsx:255` (`QuickIncidentSheet` type tile).

## Reproduction

Source audit: both set `accessibilityRole="radio"` with `accessibilityState={{ selected: ... }}` and
no `checked`. On Android with TalkBack, choose an incident type and swipe back to it: it reads
"not checked".

## Suggested fix

Use `accessibilityState={{ checked: isSelected }}` on each radio (keep `selected` off), and give the
group container `accessibilityRole="radiogroup"` with a label (the incident grid has none).

## Resolution

- Fixed in: 684526f (A35).
- Verified by: apps/compass/test/a23-moderate.test.ts (A23-006 block): radios report checked, the incident type grid is a labeled radiogroup.
