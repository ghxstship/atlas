# A23-017: The root error boundary drops the shell

## Severity rationale

Moderate. When a page throws, `apps/atlas/app/error.tsx` (the only boundary below the root layout)
replaces the sidebar, header and page with one `ErrorState` card. The accessibility tree is then a
single `alert` with a `strong` title, no `h1`, no `main`, no navigation and no skip link. A screen
reader user hears the alert once and finds nothing to navigate by. Keyboard users have only Try
again; going anywhere else means editing the address bar.

The trigger seen in the sweep is a separate functional defect: the Field Lead's `/p/NWS` and
`/p/NWS/overview` throw `Cannot read project activity: {"kind":"not-found"}` (digest 2031728187),
reported to the orchestrator.

## Location

- `apps/atlas/app/error.tsx:20` (root segment boundary renders `ErrorState` alone).
- No `apps/atlas/app/[org]/error.tsx`, so errors in any org page escape the shell layout.

## Reproduction

1. Sign in to Atlas as `field@example.com` and open `/demo-productions/p/NWS/overview`.
2. The page shows "This section did not load" with Try again. Read the accessibility tree: `alert`
   only, no heading level 1 and no landmarks.

## Suggested fix

Add `error.tsx` under `app/[org]` (and the project layout), so the shell stays and only the page
region shows the error. Give the error state an `h1` naming the page or "This page did not load", put
it in `main`, and offer Go to Home next to Try again.
