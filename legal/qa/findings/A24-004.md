# A24-004: Primary hover contrast

## Finding

`Button` variant `primary` brightens the accent on hover (`hover:brightness-110`). In the dark theme
`color.accent.default` #5B63E8 becomes about rgb(100, 109, 255), and white text on it measures
4.06:1, under the WCAG 2.2 AA 4.5:1 for 13 px text (SC 1.4.3). Light theme stays above (about 4.9:1).
The token build checks the resting pair only, so the hover pair is never checked.

axe reported it as `color-contrast` on the dialog submit buttons in journey 20 (Book dock slot) and in
the white label journey whenever the mouse rested on the button after a click.

## Expected

A hover token whose pair with `color.accent.text-on` meets 4.5:1 in both themes (for example a darker
accent on hover in dark, or the `hover overlay 0.06` opacity token on a pseudo-element that darkens),
added to `scripts/contrast-pairs.json` so the build checks it.

## Test

The Atlas journeys now park the pointer before each axe pass (resting state, as axe measures), so this
finding no longer fails unrelated journeys; it needs its own hover-state contrast check once fixed.
