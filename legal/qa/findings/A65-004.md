# A65-004: Settings sections without a surface

## Finding

`SettingsSectionPage` (`apps/atlas/components/settings/settings-page.tsx`) shows a section's registered settings
and the panels modules contribute. A section with neither renders an empty state whose action links to the same
page with `?create=1`, which nothing handles. 21 sections are in that state:

| Section                            | Backend that exists                                                                                  |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------- |
| API Keys and Service Accounts      | `api_keys`, `service_accounts`, scopes (0921, 0922, 0936) and operations                             |
| Webhooks                           | `webhook_endpoints`, signed deliveries, `webhookDeliveries.replay` (0510)                            |
| Spend Authority                    | `app.spend_authorities`, enforced in approval RPCs (0320, 0360)                                      |
| Separation of Duties               | `app.separation_of_duties_rules` registry (1150); orgs may tighten rules                             |
| Custom Fields                      | `custom_field_definitions` and values (0540)                                                         |
| Canon Extensions                   | `canon_extension_proposals` (0490); a page exists under Canon                                        |
| Data and Privacy                   | DSAR workflow, retention policies, legal holds, exports (0501, 0530)                                 |
| Templates, Usage, Partner          | Templates (1032), usage rollups (0510), partner console (1060); A59-032 and A59-020 are in progress  |
| Audit Log                          | Served by Activity, Audit log                                                                        |
| Notifications Defaults             | None: no org-level defaults or mandatory categories (A65-021)                                        |
| Departments and Disciplines in Use | None: no table records them                                                                          |
| Locations and Venues defaults      | None                                                                                                 |
| Automations                        | None (A65-010)                                                                                       |
| Personal: Security                 | See A65-002                                                                                          |
| Personal: Notifications            | `person_notification_preferences`; Gateway already renders a matrix (`notification-preferences.tsx`) |
| Personal: Calendar Feeds           | `calendar_feeds` (A65-018)                                                                           |
| Personal: Connected Apps           | `oauth_grants` (0638)                                                                                |
| Personal: Developer                | Personal API tokens: not modeled                                                                     |
| Personal: Payout and Tax           | `payout_accounts`, `tax_forms` (0730); Gateway has the form                                          |

Workspace and team settings pages (Section 4.5.6, "short pages holding only the settings their scope can
override") do not exist in the sitemap.

## Why it matters

The API and database for most of these are built and tested, but an Admin cannot reach them in Atlas: spend
limits, webhooks and API keys can be configured only through the API, and DSARs only through SQL or the API.

## Suggested fix

Contribute a panel per section through `components/settings/contributions/`, reusing the data functions that
exist (`@xos/data`). Port the Gateway notification matrix and payout form to Atlas. Model departments in use,
location defaults and personal API tokens (small tables with RLS and pgTAP). Add workspace and team settings
nodes to the sitemap (an ADR 0006 amendment). Then add the test above so no section ships empty again.
