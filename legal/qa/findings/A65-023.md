# A65-023: No PWA

## Finding

Section 4.10: "Gateway and Atlas are installable as progressive web apps, with web push and an offline read
cache." Neither app has a web manifest, a service worker or web push.

## Why it matters

Gateway users on phones (its primary audience, Section 11.12) cannot install it or receive web push.

## Suggested fix

Add `app/manifest.ts` to both apps, a service worker with an offline read cache for recently viewed pages (within
the route budgets of ADR 0027), and web push subscriptions in `push_subscriptions` with VAPID keys from the owner.

## Resolution (A96)

ADR 0052 records the decisions.

- **Manifests.** Atlas and Gateway each have `app/manifest.ts`: standalone, scope `/`, shortcuts, token colors and
  the platform brand's app icon. On an org's custom domain, Gateway wears that org's name, app icon and accent.
- **Service worker.** One source in `@xos/ui/pwa`, served at `/sw.js` and registered after hydration. ADR 0027's
  route budgets do not count it.
  - It keeps recently viewed pages per signed-in person, using the proxy's `x-xos-offline-key`.
  - It never caches a mutation, an API call, an auth page or a token link.
  - It forgets everything on sign-out, and offline it falls back to `/auth/offline`.
- **Web push (1533).** Browsers subscribe in `push_subscriptions` beside A80's Expo tokens. A browser belongs to one
  person at a time.
  - The notification dispatcher sends Web Push with VAPID (RFC 8291 and 8292 on Web Crypto) under A80's quiet hours
    and preferences, without redefining A80's claim function.
  - The keys come from `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` and `VAPID_SUBJECT`, an owner step.

Tests: pgTAP 1533, `packages/platform/test/web-push.test.ts` (keys built at runtime, payloads decrypted),
`packages/ui/test/pwa.test.ts` (the worker against a fake scope) and the Playwright journeys in
`apps/atlas/e2e/a96-first-run.spec.ts`.
