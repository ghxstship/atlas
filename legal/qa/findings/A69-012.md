# A69-012: Share link tokens and download tickets in logs

## Finding

A69-008 taught the redactor the bearer token prefixes that existed then. Share links (migration 1380) came later and
were not added:

- Atlas serves a share link at `/share/xshr_<64 hex>` and its file at `/share/xshr_.../file`. The share routes are not
  wrapped in `observe`, but a request that throws reaches `onRequestError`, whose log line and Sentry event carry the
  path, and sampled Sentry transactions carry the URL. A failed open put a working link in the log drain and the error
  tracker.
- `api_public.open_share_link` answers a single-use download ticket `xdlt_<64 hex>`, which the file route posts to
  the file-download Edge Function. No rule matched the ticket, and none matched the `ticket`, `p_ticket`,
  `access_code` or `p_access_code` keys.
- The file route logged its failures with `console.error`, past the redactor.
- The token rules needed a word boundary before the prefix, so a token right after a percent escape (`%22`, `%2F`)
  was kept. Next sends the page's route parameters percent-encoded in its router state header on every server action
  and client navigation, and the second-factor redirect puts the path in `next=%2Fshare%2F...`.
- Sentry 11 no longer reads `sendDefaultPii`. Its defaults collect request headers, cookies, bodies, query strings
  and user fields, and copy each request header onto the root span (`http.request.header.*`). `scrubEvent` only
  redacted those span attributes by value, so the encoded router state header reached sampled transactions with the
  token in it. The A69-008 links (`/advance/`, `/sign/`, `/auth/invite/`) were exposed the same way.

Four other prefixes minted by the database were missing as well: kiosk device keys `xkio_` (migration 0340),
subprocessor notice confirm and unsubscribe tokens `xspn_` and `xspu_` (migration 1382, carried in link query
strings) and personal access tokens `xos_pat_` (migration 1432). A Bearer header was already masked, but the
same token inside an error message or a URL was not.

The database stores only SHA-256 hashes of share tokens, access codes and tickets, so the audit trail holds none of
them.

## Impact

Anyone who reads logs or error reports (staff, the log drain, the error tracking subprocessor) could open a shared
file. A link with an access code still needs the 6-digit code, but Public and Internal links may have none. A
download ticket is good for one use within 2 minutes. A kiosk key still needs a member's PIN to punch, and a
personal access token acts as its owner.

## Fix

- The redactor replaces `xshr_`, `xdlt_`, `xkio_`, `xspn_`, `xspu_` and `xos_pat_` tokens of 16 or more hex characters
  with `[token]`, like the A69-008 prefixes. No word boundary is needed before a prefix, so a token after a percent
  escape is replaced too.
- Whatever follows a leading `/share/` in a path or URL becomes `[token]`, so a mistyped or truncated link is
  dropped too, as A84 does for `/ical/`. `/usr/share/` and `file:///usr/share/` in a stack trace are kept.
- The keys `ticket`, `p_ticket` and `*download_ticket`, and any key ending in `access_code`, are replaced whole.
  `ticket` and `access_code` query parameters are redacted too.
- `sentryInitOptions` sets Sentry's `dataCollection`: no user fields, cookies, bodies, query strings, GraphQL or AI
  payloads, database query data, queue arguments or stack frame variables, no response headers, and only the
  request headers `scrubEvent` keeps.
- `scrubEvent` drops every `http.request.header.*` and `http.response.header.*` attribute outside those headers from
  the trace context and from each span, and redacts span descriptions.
- The file route logs through the Atlas redacting logger, not the console.
- The email rule's local part is bounded at 64 characters (RFC 5321), so a long run with no `@` no longer takes
  quadratic time. The new `/share/` rule checks its lookbehind only where `/share/` occurs.
- The Edge bundle, which carries the redactor, is regenerated.

## Residual

The hosting platform's own request log (Vercel, forwarded to the log drain under ADR 0033) records the path of every
request, `/share/<token>` included, and the redactor cannot reach it. The same holds for the A69-008 paths
(`/advance/`, `/sign/`, `/auth/invite/`) and `/ical/`. Open item: mask those path segments in a drain-side transform,
or move the tokens out of the path.

## Test

- `redact.test.ts` checks each new prefix in both cases, the share page and file paths, a full URL, a mistyped link,
  a JSON body with a ticket, a subprocessor confirm link, the new keys and query parameters, an encoded router state
  header, single and double encoded `next=` redirects, and that `/usr/share/`, `file:///usr/share/`,
  `/files/share/new`, `ticket_id` and `support_ticket_id` are kept. A timing case keeps long near-matches linear.
- `logging-and-errors.test.ts` checks that `scrubEvent` drops the router state, user agent and response header
  attributes from the trace context and spans, keeps `accept`, and leaves no token in the event.
- `sentry.test.ts` checks the `dataCollection` options.
- Each test fails on the code before this fix.
