# A65-005: Search finds pages, not work

## Finding

Section 11.7 search supports quoted phrases and the operators `kind:`, `state:`, `phase:`, `dept:`, `urid:`,
`owner:`, `project:`, `is:blocked`, `due:<7d`, groups results by type, and shows the last 50 records each user
viewed before they type. Section 11.10 item 1 has search find records, people, pages, settings and actions, and
Section 5 puts pgvector semantic search over documents and SOPs in the stack.

The command menu (`apps/atlas/components/shell/shell-command.tsx`) lists navigable sitemap pages and help articles
only. A59-015 (in progress: A60 to A62) adds record and people results and a few verbs. Beyond it:

- no operator grammar or quoted phrases;
- no record of recently viewed records;
- individual settings are not searchable (Section 11.11 Settings target "any setting reached in 1 search");
- no `vector` column or embedding anywhere; full text exists only for the handbook (0804);
- Gateway and Compass have no record search.

## Why it matters

Search first is the first shared habit in Section 11.10. Without operators and recents the 11.11 targets for
records and settings cannot be met.

## Suggested fix

A search RPC over records, people and documents that reads with the caller's own RLS, parsing the operator
grammar in `@xos/ia` or `@xos/data`; a `recent_views` table (or reuse of `activity_events`) for the last 50;
setting keys and labels in the command index; embeddings for documents and SOPs in a `vector` column filled by a
worker, with the semantic query behind the same RPC.

## Resolution (A87, RRR-132)

- **One search RPC.** `app.global_search` (migration 1440) is SECURITY INVOKER, so every row is read under the
  caller's own row level security. It covers records, incidents, people, documents, SOPs and handbook articles,
  ranks by text relevance times recency, and puts a key match (`NWS-12`) first. GIN indexes cover exactly the
  expressions it reads.
- **Operator grammar.** `@xos/data/search-query` parses `type:` (`kind:`), `project:`, `assignee:` (`owner:`),
  `status:` (`state:`), `phase:`, `urid:`, `dept:`, `is:`, `before:`, `after:` and `due:` (with Spanish aliases),
  quoted phrases and minus negation. Dates resolve on the org's calendar in the database.
- **Recents.** `app.recent_views` keeps the last 50 things each person opened per org: records, incidents,
  documents, SOPs and handbook articles. Rows go after 90 days and when the person is deleted. The command menu
  lists them before anything is typed.
- **Settings.** The command menu matches setting labels and keys from the registry. Each result opens the
  setting's page with `?setting=<key>`, which focuses the field.
- **Semantic search.** `app.search_embeddings` holds a pgvector `vector(384)` for each published document, SOP
  and handbook article. The `search-embed` Edge Function fills it with Supabase's built-in gte-small model, so no
  text goes to a new subprocessor. Matches above the similarity floor blend into the same RPC. It stays off until
  an Admin turns on `search.semantic_enabled`, and no Restricted column is ever embedded.
- **UI.** The Atlas command menu shows operator chips and hints and works fully from the keyboard. It still loads
  on demand. Gateway's menu is unchanged: Gateway has no record search for operators to narrow (follow-up).
