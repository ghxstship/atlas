# A65-021: Notification configuration is not where the spec puts it

## Finding

Section 3.15 makes `packages/schemas/notification-kinds.yaml` the single source of notification kind rows, the
preference matrix and the templates index. The file does not exist; kinds are rows in SQL reference tables
(`private.notification_categories`, `private.notification_templates`, 0520) with copy in the `email` catalog. There
is one source, but not the one named, and nothing generates the preference matrix from it.

Section 4.5.6 item 29 (Notifications Defaults: org-wide defaults and mandatory categories) has no backing: no
org-level defaults or mandatory flags exist, and the settings page is an empty state. Atlas personal Notifications is
also an empty state, while Gateway renders a preference matrix.

## Why it matters

An org cannot make safety announcements mandatory or set sensible defaults for new members.

## Suggested fix

Move the kind list to `notification-kinds.yaml` with a generated seed (as `plans.yaml` does); add
`org_notification_defaults` with a mandatory flag that `private.notify` respects; reuse Gateway's matrix in Atlas.
