# A108-001: Closed lists held as text

## Severity rationale

Low. Nothing leaks and no value outside each list can be stored, because the check constraint refuses it. But
Section 3.15 rule 3 says every closed list of values (states, kinds, types, categories, units, locales) lives in a
reference table or a Postgres enum, and gate 29 blocks release on any normal form violation missing from the
register. A list held in a check constraint is invisible to the generated database types, so the apps cannot use a
generated union for it (Section 3.15 source lint: "state or kind values defined in code instead of generated types"),
and the same list is redefined in several tables: `'Atlas', 'Gateway', 'Compass'` appears four times and
`'en-US', 'es-US'` three times, although `xpms.dim_locale` already lists the locales.

A check constraint that limits an enum column to some of its values, such as `channel in ('Email', 'Push')` on
`app.notification_channel`, is not a finding: the list lives in the enum.

## Reproduction

```sql
select con.conrelid::regclass, con.conname, pg_get_constraintdef(con.oid)
from pg_constraint con
join pg_class c on c.oid = con.conrelid
join pg_namespace n on n.oid = c.relnamespace
where con.contype = 'c' and n.nspname in ('app', 'private', 'xpms') and not c.relispartition and con.conparentid = 0
  and array_length(con.conkey, 1) = 1 and pg_get_constraintdef(con.oid) ~ '= ANY \(\(?ARRAY\['
order by 1, 2;
```

Rows whose array casts each value to an enum (`::app.notification_channel`) are enum subsets and not findings.

## Suggested fix

One migration per area converts its lists:

- Lifecycle and kind lists (`campaign_state`, `delivery_status`, `send_state`, `triage_state`, `subscription_state`,
  `outcome`, `kind`, `action`, `event_name` and the like) become Postgres enums, which the database types generator
  turns into unions the apps import.
- Lists that already have a home reference it: `locale` columns reference `xpms.dim_locale`, and the four shell
  lists (`app_code`, `surface`, `web_app`) share one `app.shell` enum (`Atlas`, `Gateway`, `Compass`, plus `API` for
  sessions).
- The `subject_table` and `source_table` lists of polymorphic subjects share one enum of subject kinds.
- Canon lists in `xpms` follow the canon import's own rules (ADR 0012): a canon reference table or a `xpms` enum the
  import writes.

Once the lists are converted, add the lint named under `regression_test`.
