# A65-032: Reliability and stack items not yet done

## Finding

- **Canon caching by generation** (Section 5.1): only a module description in `packages/api/src/app.ts`; canon
  responses carry no generation in the URL and no generation-keyed cache headers.
- **Read replicas for reports and exports** (Section 5.1): no replica routing.
- **Error budget policy** (Section 5.1): the release gate rolls back on regressions; no written policy.
- **Partitions** (Section 5.1): `time_entries` and `access_scans` are still proposals in `infra/db/proposals`
  (ADR 0025 item 5); the other six tables are partitioned.
- **Data dictionary** (Sections 3.15, 7.1): every table and column is commented (now guarded by pgTAP 1280), but
  no dictionary is generated from the comments.
- **Stack deviations without an ADR** (Section 5, ADR 0001 lists them as pinned): React Hook Form, Victory Native,
  MapLibre React Native, Protomaps PMTiles and Twilio are not installed; `packages/ui-native` ships 46 components
  chosen for Compass rather than the full inventory (Section 11.4).

## Why it matters

Small individually; the deviations should be recorded so the stack table stays the truth.

## Suggested fix

Add the generation to canon routes with immutable caching; route report and export reads to a replica when one
exists; apply the partition proposals in a post-late migration range; generate the data dictionary in the docs
site from the catalog comments; amend ADR 0001 with the deviations or install what is missing.

## Fix (A94, RRR-139)

- **Canon caching.** Every canon read carries `XOS-Canon-Generation` (from `xpms.version`). With
  `?generation=<current>` the answer is cached `private, max-age=31536000, immutable`; any other generation answers
  307 to the same URL at the current generation with `no-store`; without one the answer is revalidated and names the
  cacheable URL in `Content-Location`. The runtime reads the parameter, so the frozen v1 operations are unchanged.
  The pagination guide documents it in both locales.
- **Read replicas.** `XOS_READ_REPLICA_URL` (a replica's Data API origin) sends the report worker's definition and
  row reads and the full org export to the replica, falling back to the primary when the replica errors, lags or
  leaves a table unreadable; Storage, claims and writes stay on the primary. Unset, nothing changes. Migration 1512
  declares `app.report_run_rows` stable so PostgREST serves it as GET, which a read-only standby runs; pgTAP 1512
  reads a run's rows inside a read-only transaction. No replica exists yet (an owner and cost decision), so the seam
  is unproven against a real one.
- **Partitions.** Migration 1510 places A26's conversion procedure with three additions (ids stay unique across
  partitions, a reference to no row is refused with 23503, foreign key actions are refused rather than dropped);
  1511 converts `access_scans`, whose 7-year retention now detaches whole months. `time_entries` is not converted:
  its audit trail and worker guard name the table through `TG_TABLE_NAME` and `TG_RELID`, which a partition answers
  with its own name, so audit rows would carry the partition's name and miss its Restricted column exclusions
  (`infra/db/README.md`). That needs a coordinated change to the shared trigger functions first.
- **Data dictionary.** `pnpm --filter @xos/docs dictionary:generate` writes `apps/docs/content/data-dictionary.json`
  from the catalog (887 tables and views, 9,852 columns at batch-c d096485c with 1510 to 1512); the docs site renders
  it at `/data-dictionary`, one page per table, in both locales. The CI `database` job fails when it differs from a
  freshly migrated database.
- **Stack deviations.** The ADR 0001 amendment of 2026-10-21 records each pinned library that is not installed and
  what replaced it, and the 49-component `packages/ui-native` subset.
- **Error budget policy** is not part of this fix.
