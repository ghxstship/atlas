# A59-011: Crew and other external people lose their names in Atlas lists

## Finding

Lists that join an external person (no membership in the org) show "Unnamed person" instead of
the name: Offers (Applicant column for the Demo Crew Member's accepted offers), Credentials
Issued (holders of CR-000003 and CR-000005), Scan Log, Certifications (the crew member's Arena
Rigging certificate), the Field Lead's record property "Owner: Unnamed person" on NWS-14, and a
self-billed invoice whose counterparty reads "Individual". The same person is named on other
pages (Opportunities > Pipeline shows "Demo Crew Member", Opportunities > Engagements shows
"Demo Crew Member"), so the producer cannot tell from the offer or credential lists who the row is.
This looks like the person's name being outside the reader's row level security on those joins.

## Steps

1. Sign in as owner@example.com.
2. Open /demo-productions/people/offers and /demo-productions/credentials/issued.
3. Compare with /demo-productions/opportunities/pipeline.

## Suggested fix

Read the engaged person's display name through the same API view the Pipeline uses (the org may
see the name of anyone it engages), and add a seed assertion that no list shows "Unnamed person"
for an engaged person.
