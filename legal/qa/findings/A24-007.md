# A24-007: Aurora journeys stop at the handler

## Finding

The Aurora handler takes its model client through a dependency override (`AuroraDeps.model` in
`packages/api/src/handlers/parts/aurora.ts`). The handler tests use it to cover journey 35 (blocked
permits with linked records, NO ANSWER for an unpriced element) and journey 36 (extraction with field
confidences, confirmed before saving) without calling the API. A running Atlas has no equivalent:
with no `ANTHROPIC_API_KEY` it reports Aurora unavailable, so a Playwright journey can only cover the
plan refusal (aurora.spec.ts). The real API must never be called from tests.

## Fix (A38, RRR-82)

- **Fixture model.** `apps/atlas/lib/aurora/fixture-model.ts` answers from recorded fixtures: the
  journey 35 questions (projects in US-FL-MIAMI-DADE, then their blocked permits, cited; the price of
  an unpriced budget line is NO ANSWER) and the journey 36 certificate. Anything else is NO ANSWER.
- **Impossible in production.** It is enabled only when `NODE_ENV !== "production"` and
  `XOS_AI_FAKE=1`; `createFixtureModel` throws otherwise. The API route reaches it only inside a
  literal `process.env.NODE_ENV === "production"` early return, which the production build compiles
  away: a production `.next` holds none of the fixture's strings. The unit test asserts production
  refuses it even with `XOS_AI_FAKE=1`, that any value other than `1` refuses it, and that the route
  keeps the guard ahead of the only (dynamic) import.
- **Seam.** `handlersWithAuroraModel` (`@xos/api`) rebuilds the handler sets with Aurora's operations
  bound to another model client; every other handler is the one production serves.
- **Journey 36 surface.** Atlas had no certificate extraction UI. The new-certificate drawer in
  Vendors, Insurance certificates now offers "Read a certificate with Aurora": each field with its
  confidence and provenance, Confirm and save (written through `insuranceCertificates.create` as the
  person) or Discard. Nothing is written before the confirmation.
- **Product bug found on the way.** The insurance certificate extraction target still used the
  pre-correction field names (`each_occurrence_minor`, `currency`, `expires_on`), so a confirmed
  suggestion could never be written. It now proposes the corrected create body (`insurer`,
  `policy_identifier`, `coverage_type`, `coverage_limit_minor`, `currency_code`, `valid_from`,
  `valid_to`); the eval dataset and feature test follow.

## Running the journeys

`aurora-journeys.spec.ts` runs against a development Atlas started with `XOS_AI_FAKE=1`
(`E2E_AURORA_URL`, port 3016 by default; playwright.config.ts starts it). It passes in Chromium,
Firefox and WebKit.
