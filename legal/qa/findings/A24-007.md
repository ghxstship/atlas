# A24-007: Aurora journeys stop at the handler

## Finding

The Aurora handler takes its model client through a dependency override (`AuroraDeps.model` in
`packages/api/src/handlers/parts/aurora.ts`). The handler tests use it to cover journey 35 (blocked
permits with linked records, NO ANSWER for an unpriced element) and journey 36 (extraction with field
confidences, confirmed before saving) without calling the API. A running Atlas has no equivalent:
with no `ANTHROPIC_API_KEY` it reports Aurora unavailable, so a Playwright journey can only cover the
plan refusal (aurora.spec.ts). The real API must never be called from tests.

## Proposal

A server-side seam enabled only when `NODE_ENV` is not production and an explicit
`AURORA_TEST_MODEL=fixtures` is set, answering from recorded fixtures, so journeys 35 and 36 can run
end to end in CI. Owner decides whether the seam is acceptable in the production bundle.
