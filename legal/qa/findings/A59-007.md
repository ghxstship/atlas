# A59-007: ICU braces swallow the record key tokens

## Finding

The help line under Record key format renders as "Use undefined and undefined, for example
undefined-undefined." The message is `packages/i18n/messages/en-US/settings.json` line 128,
`"help": "Use {PROJECT} and {SEQ}, for example {PROJECT}-{SEQ}."`. ICU message format reads
`{PROJECT}` and `{SEQ}` as arguments, none are passed, so each becomes "undefined". The literal
tokens need quoting (`'{PROJECT}'`) or passing as arguments. The same check in every locale file
is worth running, since the other locales were translated from this string.

## Steps

1. Sign in as owner@example.com.
2. Open /demo-productions/settings/numbering.
3. Read the help under Record key format.

## Suggested fix

Quote the tokens in every locale and add an i18n lint that flags uppercase ICU arguments that no
call site passes.

## Resolution (A61, RRR-106)

The record key tokens are quoted ('{PROJECT}'). A new i18n test fails on any ICU argument that is not a camelCase or snake_case name; it also found the RSVP count messages (Atlas and Compass) passing capitalised arguments, now going, maybe and declined.
