# A65-001: Settings that take no effect

## Finding

Section 4.5.6 defines every setting once in `packages/schemas/settings/*.yaml`, with pages, API and audit
labels generated from it. Gate 32 checks that the registry, the database definitions and the pages agree. Nothing
checks that a setting does anything.

A65 searched apps, packages and migrations for every one of the 55 setting keys, leaving out the definitions
(`define_setting`, the YAML), the generated files, the catalogs and the tests. 41 keys have no reader. People can
change them, the change is audited, and the product behaves the same:

| Area                          | Settings with no effect                                                                                                                                        |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Security (Settings, Security) | `security.mfa_policy`, `security.session_hours`, `security.idle_timeout_minutes`                                                                               |
| Time and attendance           | `time.geofence_required`, `time.kiosk_enabled`, `time.photo_on_punch`, `time.rounding_minutes`                                                                 |
| Scheduling                    | `scheduling.allow_swaps`, `scheduling.swap_requires_approval`, `scheduling.open_shift_claiming`                                                                |
| Payroll                       | `payroll.pay_period`, `payroll.week_start`                                                                                                                     |
| Gateway and marketplace       | `gateway.marketplace_visibility`, `gateway.ratings_enabled`                                                                                                    |
| Communication                 | `communication.feed_reactions_default`, `communication.feed_comments_default`, `communication.message_retention_days`, `communication.auto_translate`          |
| Help and support              | `help.support_email`, `help.support_hours`, `help.custom_link`                                                                                                 |
| Numbering and general         | `numbering.record_key_format`, `numbering.document_number_padding`, `org.invoice_number_prefix`, `org.legal_name`, `org.default_workspace`, `shell.start_page` |
| Localization and views        | `locale.date_format`, `locale.units`, `shell.density`                                                                                                          |
| Personal accessibility        | `me.text_size`, `me.high_contrast`, `me.reduced_motion`, `me.haptics`, `me.sounds`, `me.captions`                                                              |
| Personal other                | `me.out_of_office.enabled`, `.starts_on`, `.ends_on`, `.auto_reply`, `me.shortcuts_enabled`                                                                    |

The 14 settings that do work include `security.ip_allowlist`, `security.auto_join_enabled`,
`access_reviews.*`, `communication.read_receipts`, `finance.self_billing_enabled`, `locale.language`,
`locale.time_zone`, `org.base_currency`, `org.fiscal_year_start_month`, `me.persona`, `me.theme` and
`approvals.requester_may_cancel`.

## Why it matters

These are the silent gaps ADR 0032 warned about. An Admin who sets "MFA required for everyone", a 12-hour session
or "photo on every punch" is told it is saved and gets nothing. Several carry legal or safety weight: the MFA
policy (Section 9), photo on punch and geofence enforcement (Section 13 kiosk and clock rules), message retention
(Section 4.5.6 item 28) and out-of-office delegation of approvals.

## Suggested fix

Take the settings area by area; each is small once its consumer is chosen:

- **Security**: enforce `mfa_policy` at sign-in and in `private.session_aal` checks (needs A65-002), and apply
  `session_hours` and `idle_timeout_minutes` in the Atlas and Gateway session refresh.
- **Time and attendance**: read the four `time.*` settings in `app.record_punch` (0941) and the kiosk RPCs, with
  pgTAP for each refusal.
- **Scheduling and payroll**: read the swap and claiming rules in the swap and open-shift RPCs (0460, 0462); seed
  pay periods and week start from the payroll settings.
- **Gateway**: apply `marketplace_visibility` as the default posting visibility. `ratings_enabled` needs an owner
  and counsel decision first: turning ratings off for both sides may read as suppressing reviews (Section 14.9).
- **Communication**: default new feed posts' reaction and comment switches; purge chat messages past the retention
  setting in the nightly retention job.
- **Help**: show the support contact, hours and custom link in the help panel's Contact Support.
- **Numbering**: use the formats in `private.next_sequence` display keys and generated documents.
- **Personal accessibility**: apply text size, high contrast, reduced motion, haptics, sounds and captions in the
  three shells' theme providers.
- **Out of office**: route approvals to the delegate and add the auto-reply to messages.
- Add an `enforced_by` field to each setting definition and a registry test that fails when it is empty, so a new
  setting cannot ship inert.

## Fixed

A76 (RRR-121, WP1) gave each setting a reader in the database or the apps, recorded as `enforced_by` in its registry file. A setting with no reader yet is `deferred` with its reason (5 of them), and `packages/schemas/test/settings/enforcement.test.ts` fails when a setting has neither. The release record of 2026-10-25 found this file still marked Open.
