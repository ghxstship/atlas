# A24-002: Journey surfaces not implemented

## Finding

These routes render the generated `SitemapPage` (a title and child links), not the feature, so the
Section 20.2 journeys that run through them cannot be automated and cannot pass acceptance:

| Journey                                                    | Route or surface                                            | State                                          |
| ---------------------------------------------------------- | ----------------------------------------------------------- | ---------------------------------------------- |
| 26 Partner, client org, wholesale billing, support session | `/partner/{partnerSlug}` and its four children              | generated stub                                 |
| 27 Import wizard with fuzzy duplicates and batch undo      | `/{org}/import`                                             | generated stub                                 |
| 28 Custom object records, board view, API read             | `/{org}/objects/{objectKey}`                                | generated stub (definitions in Settings exist) |
| 32 View as role, Why can I see this                        | no surface in Atlas                                         | missing                                        |
| 39 Cancel an org, full export, read-only banner            | Settings, Data and privacy shows the registry settings only | missing                                        |
| 57 Twenty Inbox approvals by keyboard                      | `/{org}/inbox`                                              | generated stub                                 |
| (shell) My Work and saved view pages                       | `/{org}/my-work`, `/{org}/views/{viewId}`                   | generated stubs                                |

Module index pages (`/{org}/finance`, `/{org}/crew` and others) are also `SitemapPage`, which is
their intended landing; they are not part of this finding.

## Repro

Open any route above on the demo tenant: the page shows the node title and its children only.

## Decision needed

Assign each surface to its owner. A24 writes the journeys (26, 27, 28, 32, 39, 57) as each lands;
`legal/qa/journey-coverage.md` tracks them as Missing until then.

## Resolution (A36, RRR-80)

| Journey | Surface now built                                                                                                                                                                                   | Spec                    |
| ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------- |
| 26      | `/partner/{partnerSlug}` with client orgs, default brand, usage and wholesale billing; Settings, Security support sessions for client Owners (migration 1060)                                       | `a36-partner.spec.ts`   |
| 27      | `/{org}/import` wizard on the A18 import schema, the imports bucket, queued detection and validation, `app.request_import_commit` and the import worker (migration 1061, `@xos/data/import-worker`) | `a36-import.spec.ts`    |
| 28      | `/{org}/objects/{objectKey}` with list, board, table and calendar views; Settings, Custom objects definitions                                                                                       | `a36-objects.spec.ts`   |
| 32      | View as role in Settings, Roles and capabilities, applied by the shell and the proxy; Why can I see this on record peeks (migration 1062)                                                           | `a36-access.spec.ts`    |
| 39      | Settings, Danger zone cancellation, the read-only window enforced on every tenant table, the read-only banner and the `/{org}/export` archive (migration 1063)                                      | `a36-lifecycle.spec.ts` |
| 57      | `/{org}/inbox` with A, R, E, H, J and K, and `notifications.act` for push actions (migration 1064)                                                                                                  | `a36-inbox.spec.ts`     |

Still open from this finding: the My Work and saved view pages (`/{org}/my-work`, `/{org}/views/{viewId}`), which were outside A36's scope, and the device half of journey 57 (a push notification on a phone, A24-005).
