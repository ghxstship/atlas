# A24-003: Module switches could not be saved

## Finding

Settings, Modules lists every sitemap item with a module, including Site Operations (module
`workforce`). `saveModulesAction` wrote a switch for every listed module, changed or not, and
`private.guard_org_module_state` (migration 0850) refuses any module missing from
`app.capability_modules` with `module_not_switchable`. `workforce` is not in that table, so every save
answered "This module is always on." and journey 51 (turn Hospitality off) could not pass.

## Repro (before the fix)

As an Owner of a new org, open Settings, Modules, untick Hospitality, Save modules: refused.

## Fix

The form now carries each module's starting state and the action writes only the switches the person
changed, so an untouched always-on module never blocks the save. Turning Site Operations itself off is
still refused with the same message, which is what the database says today.

## Decision needed

A29 and A30: should Site Operations be switchable? If so, add `workforce` to `app.capability_modules`
with a sidebar nav group in A29's or A30's migration range; if not, hide it from the Modules list.
