# A24-003: Module switches could not be saved

## Finding

Settings, Modules lists every sitemap item with a module, including Site Operations (module
`workforce`). `saveModulesAction` wrote a switch for every listed module, changed or not, and
`private.guard_org_module_state` (migration 0850) refuses any module missing from
`app.capability_modules` with `module_not_switchable`. `workforce` is not in that table, so every save
answered "This module is always on." and journey 51 (turn Hospitality off) could not pass.

## Repro (before the fix)

As an Owner of a new org, open Settings, Modules, untick Hospitality, Save modules: refused.

## First fix (A24)

The form carried each module's starting state and the action wrote only the switches the person
changed, so an untouched always-on module never blocked the save. Turning Site Operations itself off
was still refused.

## Decision and fix (A38, RRR-82)

Site Operations is switchable. Migration 1080 adds `workforce` to `app.capability_modules` in the
Operations group (org-level, sort order 29); no capability changes module. With every listed module
switchable, the Modules form again saves the whole set in one pass (the per-module starting-state
inputs are gone). pgTAP 1080 covers an Admin switching it off and on, a full save of every listed
module, Projects and Home staying always on, and the Member, Viewer, cross-tenant Owner and anon
refusals; pgTAP 0202 now counts 29 modules. settings.spec.ts turns Site Operations off and on again
and checks the sidebar each time.
