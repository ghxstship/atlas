# A47-002: Cognitive load over the gate 27 limits

## Finding

Section 18 gate 27 says no screen has:

- more than one primary action;
- more than 5 visible toolbar actions;
- more than 7 form fields before "More fields".

A sweep of every session route, per role, at desktop and 375 px found the problems below. No toolbar exceeded the limit.

**More than one primary action:**

- **The empty state repeats the header's primary action** (two identical primaries): dock schedule, occupancy, lost and found, invoice matching.
- **Page-specific secondary actions styled as primary:**
  - project overview: Post comment beside the gate action
  - project scope: four Add buttons
  - templates: Save as template
  - project settings: Add member
  - weather: Set threshold, Add role
  - rate cards: Save rates
  - cost centers: Record rate
  - feed: Acknowledge, Vote
  - dashboards: Open saved reports
  - custom objects
  - help and support
  - help desk
  - import: Choose a spreadsheet
  - white-label: the brand preview's sample button

**More than 7 visible fields without More fields:**

- me/profile
- me/profile-privacy (17)
- project settings (11)
- record edit (9)
- settings/modules (20 switches)
- settings/white-label (10)

**Gateway** (the same check runs in its sweep):

- sign-in and sign-up: the magic link and the password option are both primary;
- crew and vendor Home, Profile, Settings and Settings profile;
- vendor Explore and Messages;
- Explore filters and Settings profile privacy have more than 7 visible fields.

## Fixed with the check

The orchestrator fixed two causes at the same time:

- **Tour offer card:** its Start button was primary on 7 routes.
- **Chat:** each person's Message button was primary.
- **Gateway engagement lists:** the per-row Sign and shift Accept actions were primary.

Fixed on 2026-10-19:

- **Subordinate actions are now secondary:**
  - Atlas:
    - Post comment
    - Add member
    - Save as template
    - weather Set threshold and Add role
    - Record rate
    - feed Acknowledge and Vote
    - Add the field
    - Add team
    - the reconciliation statement forms
  - Gateway:
    - the profile Add forms
    - availability
- **Gateway sign-in and sign-up:** the password option is now secondary to the sign-in link (Section 11.10 item 12).
- **White-label:** the brand preview is inert, so its sample button is not counted.
- **Atlas routes now passing:**
  - project, project overview and project settings (actions)
  - templates
  - weather, cost centers and feed
  - custom objects, help and support, and white-label (actions)
- **Gateway routes now passing:** profile, sign-in and sign-up.
- **Still open:**
  - the empty-state duplicates
  - Scope
  - rate cards
  - help desk
  - dashboards
  - import
  - the Gateway home, settings, explore and messages screens
  - every long form

## Fix

- **Primary actions:** subordinate actions become secondary.
- **Empty states:** `EmptyState` uses a secondary action when the page header already carries the primary one. This regenerates its Storybook baselines.
- **Long forms:** they move fields past the seventh into a More fields accordion. White-label's preview sample is excluded from the count.
- **Tracking:** delete each route's entry in `apps/atlas/e2e/a11y/known.ts` once it passes. The sweep fails with "no longer reproduces" when an entry is stale.

## Fixed by A51 (RRR-96)

Both sweeps pass with empty known lists: Atlas, every session route per role at 1280 px and 375 px
(1,416 passed), and Gateway (192 passed).

- **`@xos/ui`:**
  - `EmptyState` takes `actionVariant` ("primary" by default). Pass "secondary" when the page header
    already carries the same primary action. Atlas `EmptyStateLink` and `EmptyPanel`, and Gateway
    `EmptyStateLink`, pass it through as `secondary`.
  - `Accordion` takes `keepMounted`, so closed sections stay in the DOM, hidden, and still submit
    with their form.
  - New `MoreFields`: the More fields section, an Accordion titled with the new catalog copy

  - New story "Patterns/One Primary Action" (an empty view under a header, and a long form with More
    fields). Its 8 baselines were added in the pinned Playwright container. No existing baseline
    changed: EmptyState, Accordion, AppShell and PageHeader re-verified.
- **Empty state under the header's primary is now secondary:** dock schedule, occupancy, lost and
  found, invoice matching (both empty states), crew time entries, import, dashboards, help desk.
- **Subordinate actions now secondary:**
  - project scope: Reconcile now

## Regressions on batch-c (RRR-133)

The first CI run of the batch-c release candidate found five screens added since A51 over the
seven-field limit, for every role at 1280 px and 375 px: settings/departments-and-disciplines (89
boxes: the ten departments, and every department's disciplines, which counted although each sat in a
closed `details`), settings/notifications (75 matrix boxes), settings/api-keys-and-service-accounts
(31 fields, the A99 key form's scopes), settings/webhooks (270 event boxes) and me/notifications (65).
Each is a long list of checkboxes, so the fix is one pattern rather than a More fields section past
the seventh box:

- **`ChoiceDisclosure`** (apps/atlas/components/settings/choice-disclosure.tsx): a group of choices
  closed behind its title and a summary of what is chosen, kept in the DOM so it still submits. Its
  content is not displayed while closed: a closed `details` only skips painting its content, whose
  boxes still have a size, so the gate 27 check counted them as shown.
- **Settings surfaces `checkboxes` fields:** a group with more than seven boxes is closed behind
  "N of M chosen", and `closed: true` closes a short one (each department's disciplines). This covers
  departments, webhook events, and the scopes of org API keys and personal tokens.
- **A99 API key form:** its scopes are a closed group the same way.
- **Notification matrix (Personal settings and org defaults):** each category is a closed group
  whose summary names the channels it is on for (and Mandatory on the org page), opened to its help
  and boxes. The boxes keep their names ("Feed by Email"), so assistive technology and the journeys
  read them as before.
- **Journeys:** a80, a86 and a99 open a group before checking its boxes (`openChoices` in
  e2e/support.ts).
- **Billing and Plan** (found once Checkout joined batch-c): the selected billing term was a primary
  button beside the current plan's Choose button, two primary actions. The term filters the plans,
  so its links are chips with the current one marked `aria-current`, as the invoice and budget
  filters are.
