# A65-031: Smaller Gateway requirements not met

## Finding

- **Supplier diversity certifications** (Section 4.4.1): optional, self-declared, with separate consent, used
  only where an org runs a program. No table or field exists.
- **Background checks through Checkr** (Sections 4.4.4, 5, 14.9): `app.background_checks` holds the result and
  reference; no Checkr connector runs the FCRA workflow.
- **Spend authority before publishing** (Section 4.4.3): open in ADR 0019; no publish path calls
  `private.approve_under_spend_authority`.
- **Swipe to save and pass** on phones (Section 11.12 Discover) and the **profile strength meter** and **social
  preview image** (Section 11.12 Reputation): not found.

## Why it matters

Each is small, but together they are visible to external users and to orgs with diversity or screening
programs.

## Suggested fix

A person- and org-owned diversity certification table with its own consent; a Checkr connector behind the
integration framework; spend authority in the opportunity publish RPC once the owner settles ADR 0019's open item;
the Gateway gestures and profile strength meter.

## Resolution

- **Supplier diversity, swipe and profile strength:** A89 (RRR-134, ADR 0045 decisions 8 to 10). Certifications are
  self-declared in `app.supplier_diversity_certifications` (1464) and shared with an org only under a separate
  `supplier_diversity` consent while it runs a program. A100 encrypted the certificate number (2011) and made a
  certification and its number one call (2350). `SwipeActions` saves and passes by touch swipe on Explore, Saved and
  Alerts, with a visible button and a single-key shortcut for each. The profile strength meter lists every missing
  step with a link to it. The social preview image is still missing (trace S11.12-01).
- **Spend authority before publishing:** ADR 0033 decision 61 settles ADR 0019's open item. Spend authority applies at
  publish only to orgs that set a spend limit for requisitions, until Atlas has a screen to set them; without that
  condition, ADR 0016's rule (no applicable limit means refusal) would refuse every publish. Migration 1623 makes
  `private.guard_opportunity` require an Approved requisition for a Contractor, Crew or Staff opportunity only where
  the org has such a limit. Elsewhere it publishes without one, and a named requisition only has to match its project
  and role. Atlas already has that screen: Settings, Spend limits adds and removes limits (A86, RRR-131,
  `apps/atlas/e2e/a86-settings-surfaces.spec.ts`). Whether the narrowing now ends, so that an org without limits can
  no longer publish such an opportunity, is for the owner, so trace S4.4-14 stays Partial.
- **Checkr:** the background check workflow through a provider is deferred (ADR 0033 decision 54). The Subprocessor
  List keeps Checkr's row, marked not in use at launch. `app.background_checks` still keeps only the result and
  reference. Trace S4.4-39, S5-35 and S14.9-03 are Deferred by decision.
