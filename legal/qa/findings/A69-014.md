# A69-014: Console logging in server code

## Finding

Atlas and Gateway log through a redacting logger (`lib/observability.ts`), but 50 places in server actions, route
handlers, the proxies and server components called `console.error` or `console.warn` with a data error, a thrown
error or a free-text message instead. A console line reaches the hosting platform's log and the log drain as written.
A database error can carry the values it refused, a storage error the object path, and an error message an email or a
token. Nothing kept new console calls out.

## Impact

Personal data or a credential in an error reached the log drain unredacted. No such value was found in the logged
errors, so the severity is Low.

## Fix

- Every server-side call now goes to `observability.logger.error` or `.warn` with the error as a field, so the
  redactor sees it. Extra values (a document kind, a suggestion id, a preference name) became named fields, and
  messages no longer interpolate values.
- The shared ESLint preset gains `xos/no-server-console`, on in Atlas, Gateway and the console app. It refuses the
  console in any module whose directive prologue does not say "use client"; tests, end-to-end specs, scripts and
  config files are exempt.
- The shared form-state modules `lib/platform/state.ts` and `lib/workflow/state.ts` are imported by client
  components too, so their `fromDataError`, which now logs, moved to server-only `data-error.ts` modules beside them.
  The browser bundle never carries the server logger.
- Client components keep the console: it is the viewer's own browser console, which no server log collects.
  `components/live/live-source.ts` has no directive but runs only in the browser, and carries a justified exception.

## Test

`no-server-console.test.ts` checks that server modules, a nested "use client" string and a console passed as a value
are refused, and that client modules and a shadowed `console` are allowed. The apps' lint runs the rule in the gate.
