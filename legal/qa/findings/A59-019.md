# A59-019: Break-glass is a dead end for an Owner without MFA

## Finding

Emergency access asks for a reason of at least 20 characters. A short reason gets a clear inline
error ("Write why you need emergency access, in at least 20 characters."). A valid reason then
returns "Verify with your second factor first, then try again." with no button, link or prompt to
verify or to enroll a factor; the demo Owner has none, and the org's MFA policy is "Optional for
everyone". The only way forward is to find Personal settings > Security on one's own. The same
flow is the way out of `/auth/network-restricted` when the IP allow-list blocks an Owner, which is
exactly when the person needs a direct path.

The IP allow-list form itself behaves well: empty and invalid entries name the problem
("Enter an address or a network like 203.0.113.0/24"), a valid network shows "Saved", and the page
says whether the current address is inside a listed network.

## Steps

1. Sign in as owner@example.com (no second factor enrolled).
2. Open /demo-productions/settings/security, enter a 20+ character reason, Take emergency access.

## Suggested fix

When verification is missing, open the step-up dialog (passkey, TOTP) in place, or link to
enrolling a factor with a return to this form.

## Resolution (A61, RRR-106)

A step-up refusal opens the second-factor panel in place (Settings > Security and the network-restricted page): verify a code from an enrolled authenticator app, or enrol one (QR and key) and verify it; the session rises to aal2 and the request is retried. Personal settings > Security lists and adds authenticator apps.
