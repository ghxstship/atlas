# A38-004: Journey 29 stops after the saved report

## Finding

Journey 29 places a saved report on a dashboard and schedules it by email as PDF. The tables exist
(`app.dashboards`, `app.dashboard_tiles`, `app.report_schedules`, `app.report_schedule_recipients`,
migration 0550) and the OpenAPI document lists `/dashboards`, `/dashboard-tiles` and
`/report-schedules`, but:

- the API serves none of them: each answers 404 "No operation is served at this path";
- Atlas has no dashboard page and no schedule control on a saved report;
- there is no recipients operation, and nothing turns a due schedule into a report run or an email;
- the report-run worker (1050) renders CSV only; PDF runs fail with a message naming CSV.

So no step after "save" can be automated, and no email can reach the local inbox.

## Proposal

A15: handlers for the three resources (table handlers suffice) and a recipients operation; a
Dashboards page placing saved reports as tiles; a Schedule panel on a saved report. A35: a PDF
renderer for runs. A18: a scheduler job that queues a run for each due schedule and an email with
the result for each recipient through the existing mail path (Inbucket locally).
