# A38-004: Journey 29 stops after the saved report

## Finding

Journey 29 places a saved report on a dashboard and schedules it by email as PDF. The tables exist
(`app.dashboards`, `app.dashboard_tiles`, `app.report_schedules`, `app.report_schedule_recipients`,
migration 0550) and the OpenAPI document lists `/dashboards`, `/dashboard-tiles` and
`/report-schedules`, but:

- the API serves none of them: each answers 404 "No operation is served at this path";
- Atlas has no dashboard page and no schedule control on a saved report;
- there is no recipients operation, and nothing turns a due schedule into a report run or an email;
- the report-run worker (1050) renders CSV only; PDF runs fail with a message naming CSV.

So no step after "save" can be automated, and no email can reach the local inbox.

## Proposal

A15: handlers for the three resources (table handlers suffice) and a recipients operation; a
Dashboards page placing saved reports as tiles; a Schedule panel on a saved report. A35: a PDF
renderer for runs. A18: a scheduler job that queues a run for each due schedule and an email with
the result for each recipient through the existing mail path (Inbucket locally).

## Fix (A43, RRR-87)

- **Report files.** Runs render .xlsx (exceljs 4.4.0) and PDF (pdfkit 0.20.2, server only and loaded on first
  use) as well as CSV, each at `<org_id>/<run_id>.<csv|xlsx|pdf>` (1126). Money stays NULL-aware: a total
  sums the priced inputs and each row's unpriced count is its own column. The PDF renders in the Deno Edge
  runtime too (checked on block 582 with a due PDF schedule).
- **Dispatcher.** `app.queue_due_report_schedules` (pg_cron every five minutes, and the worker before each
  pass) queues a run per recipient, as that member, and an `app.report_deliveries` row; a finished run queues a
  `report.deliver` job, a failed run fails its deliveries with the reason (1127). The report-run Edge Function
  renders the runs and emails each file as an attachment: to the local Inbucket (Mailpit) with
  `XOS_REPORT_MAILPIT_URL`, or through Resend within the email allow-list. Without either, deliveries wait with
  the reason and nothing is sent.
- **API.** Handlers for `/report-schedules`, `/dashboards` and `/dashboard-tiles` (corrections
  report-schedule-columns, dashboard-owner and dashboard-tile-grid), and the additive
  `/report-schedule-recipients` and `/report-deliveries`.
- **Atlas.** Reports, Dashboards (`reports.dashboards`): dashboards per member, a 12-column grid of saved
  reports read as the viewer with NULL-aware totals; on a saved report, Add to a dashboard and Schedule by
  email with recent emails.
- **Journey 29** runs end to end: build with a NULL-aware total, dashboard, PDF schedule, email received in
  Inbucket with the PDF attached.
