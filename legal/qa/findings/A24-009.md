# A24-009: Route JavaScript over budget on every page

## Finding

Section 18, gate 10 caps route JavaScript at 200 KB gzip. Lighthouse against production builds
measured 466 to 717 KB on every key page of Atlas, Gateway and docs (`legal/qa/performance-results.md`).

The largest script on every page is one chunk of about 1.0 MB raw, 305 KB gzip (334 KB on docs). It is
the whole message catalog: every namespace in en-US and es-US, inlined by `JSON.parse`. It reaches
the browser through:

- `packages/ui/src/lib/i18n.ts`, which imports `getMessages` from `@xos/i18n`; every client component
  that imports `@xos/ui` pulls in `catalogs.generated.ts`;
- `apps/atlas/app/global-error.tsx` and `apps/gateway/app/global-error.tsx`, client components that
  import `getMessages` directly.

Atlas signed-in pages carry a second large chunk, about 98 KB gzip (349 KB raw), that is mostly Zod
schemas (391 `zod` references), which suggests `@xos/schemas` modules imported by client components.

## Repro

`pnpm --filter @xos/testing lighthouse` against `next start` builds, or open
`apps/atlas/.next/static/chunks/` after `next build` and find the chunk that begins with
`JSON.parse('{"views":{"label":"View"`.

## Expected

The browser receives only the active locale's namespaces a page uses: `@xos/ui` takes its strings
from the provider (or imports only the `ui` namespace file), the server passes the page's namespaces
to `NextIntlClientProvider`, and `global-error.tsx` imports only the strings it shows. That removes
about 305 KB gzip from every page, which brings Atlas sign-in (481 KB) and Gateway pages (519 to
530 KB) near the budget; Atlas signed-in pages also need the Zod chunk kept on the server.
