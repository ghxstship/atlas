# A54-003: refusals named for the transition rule test a different guard

## Finding

For gate 4 traceability, A54 filled in the refusal message of every `throws_ok(..., 'XR001', null, ...)` that
calls a transition RPC with a pair `private.lifecycle_transition_rules` does not hold. In 8 of them the database
refused for another reason first, so the assertion's description claims more than it tests:

| Suite                          | Assertion                                                 | Refused by                            |
| ------------------------------ | --------------------------------------------------------- | ------------------------------------- |
| 0320_finance                   | rejection only through its RPC (Approved to Rejected)     | `expense_use_approval_rpc`            |
| 0340_crew                      | an Open period cannot jump to Posted                      | `pay_period_runs_open`                |
| 0361_people                    | Filled is terminal (requisition Filled to Approved)       | `requisition_use_approval_rpc`        |
| 0361_people                    | Superseded is terminal (agreement Superseded to Signed)   | `agreement_signed_by_signer`          |
| 0460_crew_lifecycle            | a writer cannot accept for the crew member                | `shift_accept_rpc`                    |
| 0492_submittals_sponsor_assets | a Proposed submittal cannot be approved before submission | `sod_approval_requester`              |
| 0643_support_tickets           | a closed ticket is final                                  | `support_ticket_transition_forbidden` |
| 1030_approvals                 | a Retired policy stays retired                            | `approval_policy_active_exists`       |

Each one keeps its `null` message, so it still passes on any XR001. The rule each description names does hold:
each lifecycle now has another assertion that names `<lifecycle>_transition_not_allowed` or
`<lifecycle>_state_conflict`. The two that matter most are these:

- **0340 "an Open period cannot jump to Posted".** It would still pass if the rules allowed Open to Posted,
  because the open payroll runs refuse first.
- **1030 "a Retired policy stays retired".** It would still pass if Retired to Active were allowed, because
  another Active policy exists.

## Suggested fix

Make each assertion test what it says. Either set the world up so the earlier guard passes and assert the
transition code, or rename the assertion after the guard it actually hits and assert that code. For example,
retire the other Purchase Order policy before asserting `approval_policy_transition_not_allowed`.
