# A65-027: New orgs start empty

## Finding

Section 7.2: the XOS Standard Library (`std_document_library`, `std_emergency_code`, `std_enumeration`,
`std_labor_rate_card`, `std_radio_channel`, `std_role`, `std_sop`, `std_vendor_class`, `std_vendor_entitlement`,
`std_verbiage`) is "copied into each new org as editable org data".

Nothing copies it. Emergency codes are served read-only straight from canon (`emergencyCodes.list` on
`xpms.emergency_code`), so an org cannot edit its codes. SOPs, verbiage, radio channels and vendor classes start
empty (a vendor class may reference a standard class, 0330).

## Why it matters

An org cannot tailor its emergency codes, and every new org rebuilds its SOP and radio plan from nothing.

## Suggested fix

A copy step in org creation (and an "Adopt Standard Library" action for existing orgs) writing org rows with a
reference to their standard source; org-level emergency codes with numeric ordering.

## Resolution (WP18)

Migration 1612 copies each Standard Library table into the org as org data that names its standard source:

| Standard Library                             | Org data                                    | Source reference            |
| -------------------------------------------- | ------------------------------------------- | --------------------------- |
| `std_document_library`                       | `app.documents` (no version until uploaded) | `std_document_id`           |
| `std_emergency_code` (`xpms.emergency_code`) | `app.emergency_codes`                       | `code` (canon code word)    |
| `std_enumeration`                            | `app.enumerations`                          | `std_enumeration_id`        |
| `std_labor_rate_card` (`xpms.rate_card`)     | one `app.rate_cards` card and its lines     | `canon_rate_card_id`        |
| `std_radio_channel`                          | `app.radio_channel_plan`                    | `std_radio_channel_id`      |
| `std_role` (`xpms.role`)                     | `app.role_library`                          | `role_code`                 |
| `std_sop`                                    | `app.sops` (drafts)                         | `std_sop_id`                |
| `std_vendor_class`                           | `app.vendor_classes`                        | `std_vendor_class_id`       |
| `std_vendor_entitlement`                     | `app.vendor_class_entitlements`             | `std_vendor_entitlement_id` |
| `std_verbiage`                               | `app.verbiage_terms`                        | `std_verbiage_id`           |

- **New orgs.** `app.create_organization`, `app.create_client_organization` and `app.subscribe_external_account`
  copy the library in the same transaction. A sandbox is filled from its template instead (1530).
- **Existing orgs.** Settings, Canon Extensions shows how many rows of each library the org holds and offers
  **Adopt Standard Library** (`app.adopt_standard_library`, canon.extension.write). It copies only rows the org never
  held, so a second run copies nothing, an edited copy keeps its edits and a removed copy stays removed. An SOP code
  the org already uses takes the next free code; a vendor class or verbiage term the org already has keeps the
  org's own. Several of the org's vendor classes may still name one standard class, as Atlas and API v1 allow, so
  `std_vendor_class_id` stays non-unique: a standard class any of them names is not copied, and its entitlements go
  on the oldest. Standard labor rates go only on a rate card in their own currency.
- **Emergency codes** are org rows in numeric order (`sort_order`, Section 3.6). Safety, Emergency codes lists the
  org's codes and lets safety.emergency_code.write relabel, redescribe and reorder them; an org that has not adopted
  sees the canon codes. The code word stays canon, because crisis alerts and protocols name it (decision D15), and
  API v1's `emergencyCodes` keeps serving the global codes unchanged.
- **Radio plan.** A project's radio plan starts from the org's own plan when it has one.

Compass's offline reference still caches the canon emergency codes; showing the org's copies there needs a sync
source and scope rule for `app.emergency_codes` (left for a follow-up).
