# A65-007: Keyboard first, partly

## Finding

Section 11.2 principle 1: Cmd or Ctrl+K everywhere (done), every action has a shortcut, `?` shows the shortcut
sheet, G then a letter navigates modules, C creates a record in the current context, J and K move, X selects.
Section 4.10 adds a global Create menu (+ and C) offering every kind the person may create. Section 11.7 lets people
rebind shortcuts with conflict and reserved-key checks. Section 3.15 makes `packages/schemas/shortcuts.yaml` the
single source of key bindings, the shortcut sheet, command hints and docs.

Found:

- `packages/schemas/shortcuts.yaml` does not exist. Bindings are hard-coded in `shell-frame.tsx`, `aurora-center.tsx`,
  `inbox-view.tsx`, `RecordList` and the `SHORTCUTS` constant in `help-panel.tsx`.
- No G sequence handler in any shell.
- The `C` shown on create buttons is a label: `Button`'s `shortcut` prop renders keys and binds nothing.
- No global Create menu.
- Personal settings, Keyboard Shortcuts holds only `me.shortcuts_enabled`, which nothing reads; `ShortcutEditor`
  is unused. `shortcut_bindings` (Section 7.3) does not exist.

## Why it matters

Keyboard first is the first design principle and the basis of the 11.11 target "create and fully classify a
record in under 10 s, keyboard only".

## Suggested fix

Create `shortcuts.yaml` with a generator for the binding map, the shortcut sheet and command hints; a shell-level
dispatcher (G sequences, C, +) driven by it; the global Create menu listing creatable kinds from capabilities;
`shortcut_bindings` per person with `ShortcutEditor` in Personal settings; honor `me.shortcuts_enabled`.

## Resolution

A81 (RRR-126) made `packages/schemas/shortcuts.yaml` the single source of key bindings, with the generated
registry, the Atlas key handler (G then a letter, C, `?`, Mod+K), the global Create menu, the shortcut sheet,
command menu hints and rebinding with conflict and reserved-key checks in Personal settings, Keyboard Shortcuts
(`app.shortcut_bindings`, migration 1370).

A125 (RRR-170) closes the rest:

- Every record action has a default and a bindable shortcut: change state (S), assign owner (A), comment (M),
  edit title (E), open the full page (O), copy the link (L) and move to Trash (Mod+Backspace). So does every view
  action on a collection: switch view (V), open the filters (F), save the view (Shift+S) and export (Shift+E).
  The record and collection templates and the side peeks are the regions, and the control carries
  `data-shortcut="<id>"`; the key handler clicks or focuses it (`packages/ui/src/lib/shortcut-targets.ts`), so a
  feature binds its control by carrying the attribute.
- The marked controls are shared ones: state moves in the collection kit, finance, logistics, permits, asset
  units, engagements, projects and Work; Work's owner, title and Trash controls and logistics' record delete;
  both comment composers; the side peek's Open full, Copy link and state. Copy link on a full record page copies
  its address. A record page whose module has no control for an action (most have no inline title, owner or
  Trash control) leaves that key alone, so those keys act on Work records and wherever a module adds the
  attribute to such a control.
- Gateway answers G then a letter for its eight destinations and keys for the account panel and the organization
  switcher, built on the server from the registry for the destinations the person may open.
- The keyboard help articles (Atlas `keyboard-navigation`, Gateway `settings-keyboard-shortcuts` and
  `getting-around`, en-US and es-US) hold shortcut lists generated from the registry; each shell's help test fails
  when a default key changes without the articles.
