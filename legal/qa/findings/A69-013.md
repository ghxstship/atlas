# A69-013: Share links on watermarked copies

## Finding

Section 8.6 delivers a Confidential or Restricted PNG or JPEG as a PDF that names who received it and when. Every
generated document also carries a record link, printed as text and drawn as a QR code, that "opens the record for
anyone with access" (ADR 0031, `DocumentModel.facts.recordUrl`). A copy downloaded inside Atlas links to
`/files/{version}`, which answers only a signed-in member who may see the file.

The share link file route passed `/share/{token}` instead. Every watermarked copy opened from a share link therefore
carried the link itself, `xshr_` token and all, on the page and in the QR code.

## Impact

Only a Confidential file is watermarked through a share link: a Restricted file is never shared, and the watermark
covers only Confidential and Restricted files (`private.watermark_required`). A Confidential link always asks for
its 6-digit access code, so whoever received a forwarded copy also needed the code to open the link again, until it
expired, was revoked or locked after 5 wrong codes. The exposure was the link itself, a credential that should not
travel with a copy meant to deter forwarding, so the severity is Low.

## Fix

- Migration 2000 recreates `api_public.open_share_link` with the opened file version as one more result column.
- `openShareLink` answers it as `versionId`.
- The file route links the copy to `/files/{version}` through `copyRecordUrl`, which the in-app download route now
  shares. Without a version (before migration 2000 is applied) the copy links to the Atlas home page, never to the
  share link.
- A version id is a pseudonymous key that opens nothing without access (ADR 0003).
- The org can trace a found copy back to the exact file version.

## Test

- `2000_share_link_record_url.test.sql`: an open answers the opened version; a refusal answers none; the function
  keeps 1380's columns in order with the version last, its grants and comment; a read-only call is still refused.
- `share-link-file.test.ts`: the copy's record link is `/files/{version}` and never holds the token; it falls back to
  the home page without a version; a failed open goes to the redacting logger.
- `share-links.test.ts`: the data layer answers the version, or null when the database names none.
