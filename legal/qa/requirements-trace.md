# Requirements trace (Sections 3 to 17)

A65 (RRR-110), audited on main 7ccd1fd9 (2026-10-19 to 2026-10-20). This file traces every concrete feature
requirement in the functional sections of `docs/spec/XOS_4.0_Build_Prompt.md` to the code that implements it.
Section 18 gates are in [gate-status.md](gate-status.md) and Section 20 journeys in
[journey-coverage.md](journey-coverage.md); rows here cite them as evidence where they apply, and do not repeat them.

## Method

- **Extraction.** Each "must", "every", enumerated feature list, settings list, role capability and page list in
  Sections 3 to 17 became one row with a stable id: `S{section}-{nn}` (for example `S4.5.6-20` is the twentieth
  requirement traced in Section 4.5.6). Lists whose items share one implementation (the module pages of Section
  4.5.5, the table names of Section 7.4) are one row; lists whose items stand alone (the 42 org settings) are one
  row each. Paraphrases only; the spec is the authority.
- **Evidence.** Migrations and tables (a fresh `supabase db reset` on a Postgres-only stack), API operations
  (`packages/api/openapi/v1.json`, 1,528 operations, all handled), sitemap routes and the page files behind them,
  pgTAP suites, vitest, Playwright and Maestro journeys, ADRs and owner decisions. A requirement is Met only where
  implementing code was found, and in almost every case a test that exercises it. Names alone were never taken as
  evidence: where a table, component or setting existed but nothing used it, the row says so.
- **Systematic checks** that found most of the gaps:
  - every registered setting was searched for a consumer outside its definition, the settings UI and the
    catalogs (41 of 55 have none, [A65-001](findings/A65-001.md));
  - every Atlas settings section was checked for registered settings or a contributed panel (21 render only an
    empty state, [A65-004](findings/A65-004.md));
  - every `packages/ui` component was checked for use in an app (11 that carry spec behavior are used by none);
  - every notification kind was listed from `private.notification_templates`, and every pg_cron job and Edge
    Function was listed, to see which promised reminders, alerts and workers run at all;
  - every table named in Sections 7.2 to 7.4 was matched against the catalog (equivalent names accepted where the
    Section 7.3 name mapping or an ADR allows them).

## Statuses

- **Met**: implemented, with the evidence named.
- **Partial**: part is implemented; the row names what is missing.
- **Missing**: nothing implements it.
- **Deferred by decision**: an ADR or owner decision defers or replaces it; the row cites it.
- **Blocked on owner**: needs an owner account, secret, decision, hire or paid service.

Rows that another agent is fixing now say "in progress" with the owner: A60 to A62 (visual-review findings
A59-001 to A59-033) and A63 (A54-002, A54-003, A53-001 and the upload staging bucket). Every Partial or Missing
row names its follow-up: an A65 finding, an in-progress finding, a gate, or an owner step.

### What the counts mean

The backend is broadly complete: every Section 7.3 and 7.4 entity has a home (bar ten 1.3 product tables), every
documented operation has a handler, and the Section 7.5 invariants are registered and tested. The gaps cluster in
five places:

1. **Settings that do nothing.** 41 registered settings are stored and audited but read by nothing, among them the
   MFA policy, session lifetime, geofence and photo-on-punch rules, swap rules and the personal accessibility
   preferences ([A65-001](findings/A65-001.md)). 21 settings sections show only an empty state although the
   database and API behind most of them exist ([A65-004](findings/A65-004.md)).
2. **Authentication.** No MFA enrollment, no passkeys, no SAML sign-in, no SCIM endpoint and no OAuth 2.1 server,
   so every step-up check (Restricted export, 1099, break-glass) is unreachable in practice
   ([A65-002](findings/A65-002.md)).
3. **Workers and channels that were never deployed.** The integration worker, the SMS and push senders, the
   saved-search matcher, expiry reminders, the day-90 deletion job and the calendar feed route exist as libraries,
   tables or flags only ([A65-013](findings/A65-013.md), [A65-012](findings/A65-012.md),
   [A65-008](findings/A65-008.md), [A65-015](findings/A65-015.md), [A65-018](findings/A65-018.md)).
4. **Interaction model.** Keyboard navigation and creation, global search, bulk edit, undo, context menus,
   co-editing and live updates are absent or partial in the web shells ([A65-007](findings/A65-007.md),
   [A65-005](findings/A65-005.md), [A65-006](findings/A65-006.md)).
5. **Whole surfaces.** The operator console ([A65-009](findings/A65-009.md)), automations
   ([A65-010](findings/A65-010.md)), Work Details ([A65-003](findings/A65-003.md)) and several Compass features
   ([A65-011](findings/A65-011.md)).
