# Compass: iOS privacy manifest and required-reason APIs

How Compass meets Apple's privacy manifest rules (required since May 2024 for every upload). Prepared by A68 (RRR-113) on main 7ccd1fd9 with Expo SDK 57.0.27, React Native 0.86.3 and Xcode 26.6.

## Where the manifests come from

| Bundle                                        | Manifest                                                                    | How it is built                                                                                                                                                                                                                                                             |
| --------------------------------------------- | --------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Compass.app`                                 | `ios/Compass/PrivacyInfo.xcprivacy`                                         | Generated by `expo prebuild` from `app.json`, `ios.privacyManifests` (the SDK 57 mechanism). Then `pod install` merges the manifests of every pod into it (React Native's `privacy_file_aggregation_enabled`, on by default in the Expo Podfile). EAS Build runs both steps |
| `ClockActivity.appex` (widget, Live Activity) | `targets/ClockActivity/PrivacyInfo.xcprivacy`                               | Committed. `@bacons/apple-targets` adds the whole `targets/ClockActivity` folder to the extension as a synchronized group, so Xcode copies the file into the extension bundle                                                                                               |
| `OpenSSL.framework` (SQLCipher's crypto)      | Shipped inside the `OpenSSL-Universal` xcframework, signed by its publisher | OpenSSL is on Apple's list of SDKs that need a manifest and a signature. Both are present (checked with `codesign -dv`)                                                                                                                                                     |

## Required-reason APIs

Found by reading every pod's manifest and searching the native sources of every iOS module Compass links (Expo modules, React Native, op-sqlite, PowerSync, Reanimated, Worklets, Screens, Safe Area, SVG, `@bacons/apple-targets`, and Compass's own `modules/compass-live-activity` and `targets/ClockActivity`).

| Category                                      | Reasons in `app.json`        | Who uses it                                                                                                                                                                                                                                                       |
| --------------------------------------------- | ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `NSPrivacyAccessedAPICategoryUserDefaults`    | `CA92.1`, `1C8F.1`           | `CA92.1`: React Native, `expo-constants`, `expo-notifications` (the app's own defaults). `1C8F.1`: Compass's Live Activity module and `@bacons/apple-targets` ExtensionStorage read and write the App Group `group.pro.ghxstship.compass`, shared with the widget |
| `NSPrivacyAccessedAPICategoryFileTimestamp`   | `C617.1`, `0A2A.1`, `3B52.1` | `C617.1`: React Native, folly, glog, boost, `expo-application`, and SQLite's `stat()` on Compass's own database files (op-sqlite ships no manifest). `0A2A.1` and `3B52.1`: declared by `expo-file-system` for its file API                                       |
| `NSPrivacyAccessedAPICategorySystemBootTime`  | `35F9.1`                     | React Native timing and boost, to measure elapsed time inside the app                                                                                                                                                                                             |
| `NSPrivacyAccessedAPICategoryDiskSpace`       | `E174.1`, `85F4.1`           | `E174.1`: SQLite's `statfs()` before writing (op-sqlite and SQLCipher) and `expo-file-system`. `85F4.1`: declared by `expo-file-system`                                                                                                                           |
| `NSPrivacyAccessedAPICategoryActiveKeyboards` | none                         | Not used                                                                                                                                                                                                                                                          |

The widget extension uses only `UserDefaults(suiteName:)` on the App Group (`1C8F.1`); its manifest declares exactly that.

`test/store-release.test.ts` fails if a dependency's manifest declares a reason that `app.json` lacks, if the widget's manifest drifts, or if the SQLite reasons disappear. When a dependency is added or upgraded, run `pnpm --filter @xos/compass test` and add any reason it reports.

## Tracking and collected data

- `NSPrivacyTracking` is `false` and there are no tracking domains. Compass never shows the App Tracking Transparency prompt.
- `NSPrivacyCollectedDataTypes` lists the same data types as the App Privacy answers (`store/ios/app-privacy.md`), each linked to the user, not used for tracking, for App Functionality only.

## Purpose strings (`NS*UsageDescription`)

Set in `app.json` (`ios.infoPlist` and the plugin options), in plain language, and checked by `test/store-release.test.ts`:

| Key                                            | Text                                                                                                                                                | Why it is there                                                                                                                                                         |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `NSCameraUsageDescription`                     | Compass uses the camera to scan badges, asset tags and barcodes, and to take incident and inspection photos.                                        | Scan tab, incident and inspection photos                                                                                                                                |
| `NSMicrophoneUsageDescription`                 | Compass records voice notes for incident reports when you hold the microphone button.                                                               | Voice notes                                                                                                                                                             |
| `NSLocationWhenInUseUsageDescription`          | Compass checks that you are at the venue when you clock in and pins incident reports to where they happened.                                        | The only location permission Compass asks for                                                                                                                           |
| `NSLocationAlwaysAndWhenInUseUsageDescription` | Compass uses your location only while the app is open, to check that you are at the venue when you clock in. It never tracks you in the background. | Never requested. `expo-location`'s binary references the Always API, and App Store Connect rejects a binary without the key (ITMS-90683), so the text says what is true |
| `NSLocationAlwaysUsageDescription`             | Same as above                                                                                                                                       | Same reason                                                                                                                                                             |
| `NSMotionUsageDescription`                     | Compass does not use motion or fitness data.                                                                                                        | Never requested; `expo-location` adds the key by default                                                                                                                |
| `NSFaceIDUsageDescription`                     | Compass uses Face ID to unlock your work data on this device.                                                                                       | Biometric Unlock and the deletion check                                                                                                                                 |

- **Photos:** no `NSPhotoLibraryUsageDescription`. Compass takes photos only with its own camera view (`expo-camera`) and never reads or saves to the photo library.
- **Notifications:** iOS has no purpose string for notifications. Compass asks in context, from the Inbox (`useNotificationPermission`).
- **Background modes:** none. `expo-audio`'s background playback is off (it had added `UIBackgroundModes: audio`, which App Review rejects when nothing plays in the background) and location never runs in the background. The Live Activity needs no background mode.

## Encryption and export compliance

- **Fixed by A68:** the offline database was not encrypted on iOS. op-sqlite's podspec reads its options from the first `package.json` above its own folder, which in this pnpm workspace is the repository root, not `apps/compass/package.json`, so the iOS build used plain SQLite while Android used SQLCipher. The root `package.json` now carries the same `"op-sqlite": { "sqlcipher": true }`, `pod install` reports "using SQLCipher" and links `OpenSSL-Universal`, and a test keeps both settings equal. Finding: `legal/security/findings/A68-001.md`.
- **What Compass encrypts:** HTTPS through the operating system, the Keychain, and the SQLCipher database (AES-256 through OpenSSL, a standard algorithm).
- **App Store Connect asks, per build, until `ITSAppUsesNonExemptEncryption` is set.** The expected answers, for the owner and counsel to confirm: the app uses encryption; it uses standard encryption algorithms in addition to the operating system's; it does not use proprietary algorithms. Apple then asks whether the app will be on the App Store in France, which needs a French encryption declaration. `app.json` leaves `ios.config.usesNonExemptEncryption` unset until counsel confirms, so each TestFlight build asks once (open question 1 in `store/README.md`).

## Other notes

- `@powersync/react-native` is a Compass dependency, so its pod and the `powersync-sqlite-core` binary framework are linked, although no Compass code imports it (the offline store is op-sqlite with `@xos/sync`). That framework ships no manifest or signature; Apple requires them only for SDKs on its list, which it is not on.
- `NSPrivacyAccessedAPITypes` reasons that only a dependency needs (for example `85F4.1`) stay declared, because the aggregated manifest would add them at `pod install` anyway and App Review only rejects missing reasons.
