# XOS 4.0 release checklist (Wave 7)

The checklist for the v4.0.0 release: every Section 20.3 criterion and every Wave 7 exit item (Section 19.2), each with its status and evidence. Prepared by A55 (RRR-100) on main 7ef369f plus the A55 branch, 2026-10-19. The orchestrator updates the Status and Evidence columns as each step happens, and the build report ([BUILD_REPORT.md](BUILD_REPORT.md)) links here. Gate-by-gate detail is in [legal/qa/gate-status.md](../legal/qa/gate-status.md); how to perform each step is in [infra/runbooks/production.md](../infra/runbooks/production.md).

Statuses:

- **Done**: happened, with evidence.
- **Ready**: everything the repository can hold is in place; the step waits only on the release itself (the tag, a deploy).
- **Partial**: some of it is evidenced; the gap is named.
- **Blocked on owner (OWNER)**: needs a decision, an account, a secret or a paid service that only the owner can provide. Named in the last section.
- **Not started**.

## Release day, in order

Each step links to the runbook section that performs it.

- [ ] Preflight: CI green on the tagged commit, release drill report attached, no open High or Critical finding, error budget intact (production runbook, Preflight).
- [ ] Gate 20: `infra/ci/oasdiff.sh` passes (before the first tag it reports no baseline and passes).
- [ ] Tag `v4.0.0` on `main`.
- [ ] Migrations to staging, then production (`supabase db push`, the owner typing the database password; the Supabase GitHub integration is not connected, ADR 0033 decisions 48 and 75); key-table fingerprints saved.
- [ ] Edge Functions deployed and secrets present (names only); worker schedules confirmed.
- [ ] Atlas through its Rolling Release (5, 25 and 100 percent, each stage approved by hand when the gate says promote); Gateway promoted with Instant Rollback ready; docs and console promoted (ADR 0033, decision 50; production runbook, Deploy order, step 3).
- [ ] `publish-packages.yml` approved by the owner; `npm view @xos/sdk@4.0.0` and the PyPI page show the release with provenance.
- [ ] Compass in TestFlight internal testing and Play internal testing: `pnpm --filter @xos/compass release:ios` and `release:android` (Compass store release).
- [ ] Smoke test as a real user; release notes posted; this file and the build report updated with deployed URLs and package versions.

Cutover to real users, once, with the first production release (each step is in the runbook named):

- [ ] Key rotation (`promote-to-production.md`, step 12; ADR 0033, decision 44): the owner confirms the moment. It signs everyone out, stops the old anon and service keys at once and cannot be undone; replace `xos_worker_key`, `XOS_API_JWT_SIGNING_KEY`, `SUPABASE_ANON_KEY` in the Vercel projects `atlas`, `gateway` and `console`, and `EXPO_PUBLIC_SUPABASE_ANON_KEY` in EAS straight after.
- [ ] Hosted Auth: confirm email on, and the email rate limit at about 100 an hour through Resend, raised after watching the Auth logs (`promote-to-production.md`, steps 6 and 8; decisions 42 and 43).
- [ ] DMARC at `_dmarc.mail.ghxstship.tech`: `p=none` with reports to the owner's mailbox; `p=quarantine` after two to four clean weeks (production runbook, Email from mail.ghxstship.tech; decision 46).
- [ ] Email to real recipients: `XOS_EMAIL_DELIVER_TO_ANY=true` in production once `mail.ghxstship.tech` passes Resend's SPF, DKIM and DMARC checks and `XOS_POSTAL_ADDRESS` is set (decision 41).
- [ ] Texts to real recipients: `XOS_SMS_DELIVER_TO_ANY=true` in production once Twilio approves the 10DLC campaign (decision 65).
- [ ] `status.ghxstship.tech` points at the GitHub Pages status page (`infra/ci/README.md`, Repository settings; decision 72).
